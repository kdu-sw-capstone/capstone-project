FOCURVE 0.1.25 integrated-user-lifecycle — 신규 설치 검토 후보, 실제 수용 전

이 패키지는 R3 기능 코드를 기반으로 사용자 팝업과 신규 설치·정상 종료 경로를 구현한 후보입니다.
기존 33/33·99/99 결과는 원래 범위의 증거이며 이 후보의 실제 설치 완료를 뜻하지 않습니다.
기존 Default/Profile 2 업데이트와 59파일 적용 계획은 이 설치에 사용하지 않습니다.

필요 구성: 64비트 Windows 및 일반 Google Chrome. 이 검토 패키지의 실제 설치·Chrome 수용 결과는 ACCEPTANCE.json과 별도 실행 증거로 확인합니다.
Python·Node 24·Java 21·MySQL 8.4.8은 동봉하며 설치 후 전용 폴더의 복사본만 사용합니다. 시험용 Chrome156도 동봉하지만 기본 사용자 브라우저로 사용하지 않습니다.
일반 Chrome 프로그램은 기존 설치 실행 파일을 읽어 사용하되 기존 Default/Profile 2를 사용하지 않고 완전히 새로운 user-data-dir를 지정합니다. 자동 다운로드·호스트 서비스 등록 없음.
Microsoft VC++ x64 런타임이 없는 PC에서는 별도 설치 승인이 필요합니다. 동봉한 Microsoft 서명 설치 파일을 자동 실행하지 않습니다.
일반 Chrome의 새 설치 수용과 웹스토어 공개 배포는 아직 검증·실행하지 않았습니다. 이 후보는 개인용 로컬 설치 경로이며 웹스토어 등록판이 아닙니다.

1. 압축을 새 폴더에 풉니다. 패키지 SHA-256과 파일 Manifest를 확인합니다.
2. Install-FOCURVE.cmd를 열면 설치 범위와 현재 사용자 인증서 등록에 동의하는지 묻습니다. 런타임 경로를 지정할 필요가 없습니다.
3. Web·DB 포트는 이번 설정과 설치 결과에 표시된 값을 사용합니다. 기본 예시는 Web18447·DB18448이며, 충돌 시 중단하고 설치 뒤 임의 변경하지 않습니다.
4. 회원가입을 쓰려면 SMTP 발송 계정과 TLS/SSL 설정이 필요합니다. 설치 안내의 SMTP 질문에 본인이 값을 입력합니다. 메일 설정을 건너뛰면 외부 메일·Google·Kakao는 활성화되지 않습니다.
   Gmail 로그인 이름은 전체 이메일 주소입니다. Google 로그인 비밀번호가 아닌 Gmail 앱 비밀번호를 사용합니다. 비밀번호를 설정 파일·채팅에 넣지 않습니다. mail.enabled=true 설치 시 콘솔의 비밀번호 입력란에 직접 입력합니다.
5. 실제 신규 설치와 현재 사용자용 localhost 인증서 등록에 동의한 경우에만 INSTALL을 입력합니다.
   별도 전용 설치 폴더·프로필·DB·설치 키만 생성하며 시험 계정을 만들지 않습니다.
6. 설치 폴더의 Connect-FOCURVE.cmd를 실행해 새 제한 실행 범위를 확인하고 CONNECT로 동의합니다.
   이번 실행에 별도로 고정된 기한이 있으면 그 기한을 전달하는 승인된 안내를 따릅니다. 기본 CMD로 승인 기한을 늘리지 않습니다.
   CMD에 표시된 이번 전용 Chrome·extension 폴더·제품 연결 주소만 사용합니다. 최초 확장 로드 후 제품 연결 화면의 '서비스 시작'을 한 번 누르고 제어 탭을 유지합니다.
   이 연결 준비 자체는 서비스나 집중을 시작하지 않습니다. 기존 Start-/Stop-FOCURVE.cmd는 현재 지원되지 않는 별도 관측 경로이므로 반복하지 않습니다.
   종료 시각10분 전부터 새 START는 차단됩니다. 자동 START/END 없음.
7. 준비 완료 뒤 제품 제어 화면의 '웹 대시보드 열기'를 눌러 회원가입·이메일 확인·로그인을 진행합니다. 확장에서 계정 연결하기를 누릅니다.
   웹 승인 후 확장에서 '웹에서 승인했어요'를 누릅니다. 기존 사용자 계정·Credential을 복사하지 않습니다.
8. 비회원은 확장의 '비회원 집중·사이트·기록 관리'를 사용합니다. 가져오기는 회원 연결 후 원하는 항목만 직접 선택합니다.
9. 집중의 정상 END를 확인한 뒤 제어 탭의 '서비스 정상 종료'를 한 번 누르고 완료 문구까지 탭을 유지합니다. 종료 요청 접수는 완료가 아닙니다.
   불명확하거나 의무가 남으면 강제 종료·END·Cleanup·재시작하지 않고 원본을 보존합니다.
10. 정상 종료 완료 뒤 제어 페이지를 새로 열어 같은 기한 안에서 재기동합니다. 새 제한 실행 범위가 필요하면 정상 STOPPED 설치에서 Connect-FOCURVE.cmd로 명시 동의합니다.
   HOLD·UNKNOWN에는 적용하지 않습니다. 상세 절차는 USER-RUNBOOK-CURRENT.md를 따릅니다.

인증서: localhost 전용 인증서를 현재 Windows 사용자 My/Root 저장소에 등록합니다. 관리자·시스템 전체 저장소·방화벽 변경은 하지 않습니다.
인증서 경고를 건너뛰거나 --ignore-certificate-errors를 사용하지 않습니다. 등록 승인이 없으면 설치하지 않습니다.
비밀은 현재 Windows 사용자 DPAPI로 보호합니다. MySQL 제어 파일·개인 로그는 전용 사용자 ACL 폴더 안에만 존재합니다.
실패 설치의 자동 삭제/복원/다른 프로필 재사용 기능 없음. 전역 STOP·기존 실행 계약·실패 환경은 변경하지 않습니다.

물리 오디오 청취: PENDING, 배포 준비와 별도 관리. 실제 새 설치 수용 결과가 나오기 전 제품 완료로 표시하지 않습니다.

신규 설치 실행 준비 계약: Worker가 가져온 JavaScript 캐시에 매 실행 기한을 의존하지 않습니다. 네이티브 소유 실행기가 만든 공개 launch-context.json을 읽고 설치 ID·API·Origin·실행 ID·기한을 대조한 뒤 준비 상태를 엽니다. 열기 직전에 로컬·DB 의무도 재확인합니다. 이전 실행의 ready=true만으로 새 실행을 허용하지 않으며 같은 실행 ID의 기한 연장을 거절합니다.
