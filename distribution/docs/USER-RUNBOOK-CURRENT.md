# FOCURVE 전용 설치의 연결·사용·정상 종료

이 안내는 수정 소스를 포함한 신규 설치용입니다. 이전 HOLD·UNKNOWN 설치를 복구하거나 재로드하지 않습니다. 기준 버전의 STEP 04 실제 서비스 왕복은 통과했지만, 이번 변경본의 Chrome 전체 수용과 회원·비회원 수용은 아직 완료되지 않았습니다.

## 최초 설치 후

1. 설치 폴더의 `Connect-FOCURVE.cmd`를 실행합니다.
2. 현재 사용자 Native Messaging 등록과 전용 Chrome 연결, 최대 60분의 새 제한 실행 범위를 확인하고 동의할 경우 `CONNECT`를 입력합니다. 이 단계는 서비스를 시작하거나 집중을 실행하지 않습니다.
3. 열린 Chrome의 ‘압축해제된 확장 프로그램 로드’에서 CMD에 표시된 **이 설치의 extension 폴더**를 선택합니다. 기존 프로필이나 다른 설치의 폴더를 선택하지 않습니다.
4. CMD에 표시된 제품 연결 주소를 **방금 열린 같은 Chrome 창**에 붙여 넣습니다.
5. ‘FOCURVE 사용’의 **서비스 시작**을 한 번 누릅니다. 제품이 현재 설치·프로필·로컬 의무·독립 DB 안전과 연결을 확인합니다. 사용 중에는 이 제어 탭을 열어 둡니다. 준비 완료 후 웹 대시보드·집중 팝업 링크로 새 탭에서 사용합니다. ‘서비스 기동·종료·재기동 확인’을 일상 사용 버튼으로 반복하지 않습니다.

Gmail SMTP에는 Google 로그인 비밀번호 대신 **16자리 앱 비밀번호**를 숨김 입력란에 입력합니다. 표시용 공백은 신규 입력 때만 제거하며 기존 보호 저장값은 자동 수정하지 않습니다. 숨김 입력이 불가능한 터미널에서는 입력을 거절합니다. 회원가입용 FOCURVE 비밀번호와 Gmail 앱 비밀번호는 서로 다릅니다. 비밀번호·인증번호를 채팅에 보내지 않습니다.

## 서비스 제어 탭과 집중 팝업을 구분하기

이 절차는 정식 실행 승인이 있고 현재 로컬·DB 안전 검사와 필요한 HOLD 처리가 완료된 경우에만 사용합니다. 현재 HOLD·UNKNOWN 설치에서 아래 버튼을 누르는 안내가 아닙니다.

| 화면 | 역할 | 사용 중 유지할 것 |
|---|---|---|
| ‘FOCURVE · 서비스 제어 — 사용 중 유지’ 탭 | Windows 프로그램과 Native 연결을 유지하고 서비스를 시작·정상 종료 | 주소·탭을 그대로 유지. 실행 중 새로고침도 하지 않음 |
| ‘집중 팝업을 새 탭으로 열기’로 열린 별도 탭 | 회원·비회원 집중 시작·진행·종료 확인 | 서비스 제어 탭과 별개로 사용 |

1. 승인된 전용 Chrome의 서비스 제어 탭에서 ‘FOCURVE 사용’ 영역의 **서비스 시작**을 한 번 누릅니다.
2. **‘서비스가 준비됐습니다’**가 나올 때까지 기다립니다. ‘Windows 프로그램 연결 완료’만으로 서비스 준비가 끝난 것은 아닙니다.
3. 같은 화면에 나타난 **집중 팝업을 새 탭으로 열기** 링크를 누릅니다. 새 탭이 열리며 원래 서비스 제어 탭은 남아 있어야 합니다. 팝업 주소를 제어 탭 주소창에 붙여넣지 않습니다.
4. 새 팝업 탭에서 회원·준비 상태를 확인합니다. 집중 시작은 별도 수용 지시와 현재 안전 조건이 충족된 경우에만 한 번 누릅니다.
5. 정상 집중 종료를 확인한 뒤 **원래 서비스 제어 탭**을 선택하고 ‘서비스 정상 종료’를 한 번 누릅니다. 정상 종료 완료 문구까지 기다립니다.

주소 변경·닫기·새로고침은 모두 제어 문서를 내리므로 Native 연결을 잃을 수 있습니다. 브라우저가 이탈 경고를 표시하면 **취소/페이지에 머무르기**를 선택합니다. 경고 표시 자체는 브라우저 조건에 따라 보장되지 않습니다. 연결 단절은 서비스가 종료됐다는 뜻이 아닙니다. 실패 화면은 준비·종료 성공을 표시하거나 자동으로 재기동하지 않습니다. 뒤늦은 READY·완료 메시지도 실패 표시를 되돌리지 않습니다.

단절됐으면 서비스·집중 시작/종료·새로고침·재로드·복구를 반복하지 말고 화면 문구를 전달합니다. 재개에는 현재 로컬·독립 DB 안전 확인, **이번 단절 원인에 맞는 정식 HOLD 처리**, 수정 적용 및 새 유효 실행 승인이 필요합니다. 과거 pre-service HOLD 전이 성공이나 DB 0건만으로 이번 post-READY 단절 HOLD가 해소됐다고 판단하지 않습니다.

## 정상 종료와 다음 실행

집중 중이면 제품 팝업에서 정상 END가 완료됐는지 먼저 확인합니다. 제어 탭의 **서비스 정상 종료**를 한 번 누릅니다. ‘정상 종료 요청을 접수했습니다’는 종료 완료가 아닙니다. **‘서비스를 정상 종료했습니다. 데이터는 보존했습니다’**가 나올 때까지 제어 탭과 Chrome을 닫지 않습니다.

제품은 새 시작 차단 → Server·Extension quiesce → 현재 로컬·DB 안전 확인 → 지정 기록 필드 다이제스트 저장 → Server 정상 종료 → MySQL 정상 종료 순서로 수행합니다. 같은 실행 ID의 READY 파일은 이 모든 단계가 성공한 뒤에만 제거합니다. 실패·UNKNOWN·미해소 의무가 있으면 READY·실패 기록·잠금을 보존하며 END·Cleanup·자동 복구를 하지 않습니다.

실행 중 탭 이동·닫기에는 경고를 요청하지만, 운영체제 강제 종료·브라우저 충돌을 막는다고 보장하지 않습니다. 연결 단절은 정상 종료가 아니며, 제어 탭 닫기는 서비스 종료 명령이 아닙니다.

같은 기한 안에서 다시 시작할 때는 제어 페이지를 새로 열고 서비스 시작을 누릅니다. 새 실행 ID와 현재 안전 검사를 사용하고 기한은 연장하지 않습니다. 이전 정상 종료의 세션·접근·구간 기록 다이제스트도 비교합니다. 빈 테이블 비교만으로 실제 사용자 기록 보존을 통과했다고 표시하지 않습니다.

새 제한 실행 범위가 필요하면 정상 종료된 **같은 설치**에서 `Connect-FOCURVE.cmd`를 실행하고 새 범위에 명시적으로 동의합니다. 정상 STOPPED·이전 종료 증거·서비스 부재·설치 무결성·포트·Chrome 소유권을 검증합니다. 기존 확장·프로필·DB·SMTP는 보존하고 Native 연결 설정만 백업 후 새 범위에 결속합니다. 확장 재설치나 실패 상태 수동 변경은 하지 않습니다. 이전 종료 증거는 자격 확인용이며, 새 기동 시 제품이 현재 로컬·DB 상태를 다시 검사합니다.

정상 재연결 경로는 자동·합성 설치 시험을 통과했지만 실제 Chrome 반복 사용 수용은 아직 미검증입니다.

## 실행 범위와 실패

연결 준비 시 정한 고정 기한을 그대로 사용하고 남은 시간이 부족하면 시작하지 않습니다. 기존 집중 잠금 검증 전용 범위는 최대15분, 명시적으로 승인한 정상 사용 범위는 최대60분입니다. 자동 연장이나 무기한 상시 실행을 승인하지 않습니다. 실행 중 오류·UNKNOWN·미해소 의무가 있으면 해당 실행을 보존하고 자동 재시도·복구·END를 하지 않습니다. 설정 파일·상태·잠금 파일을 수동으로 고치거나 재설치하지 않습니다.

연결 준비가 실패하면 `native-setup.lock`과 그 시점의 원본·기록을 보존합니다. 창을 닫고 다시 시도하는 것으로 복구됐다고 취급하지 않습니다. 새 승인이나 시간 설정만으로 기존 실패 설치가 다시 실행되지는 않습니다.

## 결과의 의미

성공 문구의 ‘DB 행 수 보존’은 스키마와 행 수 비교입니다. 모든 사용자 레코드 내용 보존을 증명하는 것은 아닙니다. STEP 04 완료 판정에는 실제 Chrome 결과와 필요한 데이터 보존 증거를 함께 확인해야 합니다. 이 문서와 자동 시험 PASS만으로 실제 수용을 선언하지 않습니다.

## 기존 실행 방식과 구분

기존 `Start-FOCURVE.cmd`/`Stop-FOCURVE.cmd`는 브라우저 관측 제공자가 필요한 별도 경로입니다. 현재 이 제공자는 없으므로 해당 명령을 반복하지 않습니다. 이번 사용 절차는 **Connect-FOCURVE.cmd와 제품 제어 화면**입니다. 제품 자체 Native Messaging은 ChatGPT의 Extension 문서 접근 정책을 해제하거나 CDP·관측 도구를 제공하지 않습니다. 실제 수용은 제품 자체 검사, 사용자 정상 UI 입력, 독립 Server·DB 검증으로 진행합니다.

등록은 설치별 호스트 이름과 정확한 Extension Origin 1개를 사용하는 HKCU 항목입니다. 다른 호스트·인증서·프로필·SMTP 설정을 복사하거나 덮어쓰지 않습니다. 인증서 신뢰 등록은 별도의 최초 설치 동의 범위입니다.

물리 오디오 청취는 별도 PENDING이며 이번 기동 검증에 포함되지 않습니다. Default·Profile 2 업데이트는 별도 BLOCKED입니다.

## 연결 시간이 만료되거나 전용 Chrome을 다시 연 경우

연결 화면은 실행 승인 만료와 설정 누락을 구별해서 표시합니다. ‘Windows 프로그램 연결 완료’는 서비스나 집중 준비 완료를 뜻하지 않습니다. 이미 열린 전용 프로필을 확인하는 과정에서 다른 Chrome을 종료하거나 Default·Profile 2로 전환하지 않습니다.

PRODUCT_LOCAL_NOT_CLEAR로 보존된 설치에 대해 별도의 PRODUCT HOLD 전이 승인을 받은 경우에만, 검증된 설치 소스의 다음 명령을 사용할 수 있습니다. 이 명령은 기존 실패 범위가 만료되고 아직 전이를 시도하지 않았을 때 새 범위를 등록합니다. 승인된 상한을 임의로 늘리지 않습니다.

    runtimes\python\python.exe -I -B -X utf8 control\installer\install_core.py renew-product-hold-scope --instance . --minutes 20 --interactive

화면의 범위를 확인하고 동의할 때만 HOLD-SCOPE를 입력합니다. 새로운 Windows 소유자·정확한 전용 프로필·Chrome 실행 파일·PID·생성 시각을 검증합니다. PID 재사용·다른 사용자·다른 프로필·미확인 프로세스·기존 전이 시도는 거절합니다. 이전 Chrome 소유권과 원래 실패·잠금 기록은 백업·보존합니다. 이 작업은 Chrome을 새로 설치하거나 서비스를 기동하거나 HOLD를 해제하지 않습니다.

승인 등록에 성공하면 기존 제품 연결 탭을 Ctrl+Shift+R로 새로고침하고 ‘보존된 중단 상태 안전 확인’을 한 번 누릅니다. 확장 재설치·재로드는 하지 않습니다. 현재 로컬 상태와 신원이 확인된 뒤에만 전용 MySQL이 기동됩니다. DB는 읽기 전용 일관 스냅샷으로 현재 의무와 같은 회원을 확인합니다. 정상 DB 종료·포트 해제·마지막 로컬 확인까지 성공해야 정식 전이 영수증을 기록합니다. 결과는 서비스 종료·집중 권한 CLOSED이며 START는 별도 승인과 정상 실행 조건이 필요합니다.

UNKNOWN·인증 만료/미확정·미해소 의무가 있으면 진행하지 않습니다. 과거 재인증 PASS나 DB 0건을 현재 안전 판정으로 사용하지 않습니다. 이 명령은 회원 재인증을 자동 수행하지 않으며, 기존 재인증 전용 경로의 별도 승인과 사용자 로그인이 필요한 경우는 별도 절차로 남습니다. 실패한 전이를 새 기한으로 재시도하거나 실패 기록·잠금을 삭제하지 않습니다.

## 신규 독립 설치의 다음 실제 수용 순서 (아직 실행 승인 아님)

기존 HOLD/UNKNOWN 설치를 복구하거나 복사하는 절차가 아니다. 최신 제품 수정이 포함된 패키지를 검증한 뒤 별도 승인을 받은 신규 설치에서만 수행한다. 기존 ZIP의 자체 무결성 통과를 최신 소스 포함 증거로 사용하지 않는다.

1. 전용 설치 경로·프로필·Extension ID·Native 허용 Origin·API·callback·독립 DB와 포트·HTTPS 신원을 하나의 Manifest에 결속한다. 기존 Credential/SMTP 비밀번호/운영 DB는 복사하지 않는다. 필요한 비밀 입력·이메일 확인은 사용자에게 한 번에 안내한다.
2. 실행 시작 시 유효한 기한과 종료 여유를 등록한다. 현재 회원·로컬 원장·DNR·독립 DB 세션/잠금/Receipt를 확인한다. UNKNOWN·미해소 의무·신원 불일치면 START를 하지 않는다.
3. 서비스 제어 탭의 서비스 준비 완료를 확인하고 그 화면의 **집중 팝업을 새 탭으로 열기**를 누른다. 원래 제어 탭의 주소 변경·새로고침·닫기는 하지 않는다.
4. 회원가입/로그인/회원 연결 완료와 정책 저장을 확인한다. 첫 회원 START는 1회만 수행한다. RUNNING과 실제 정책 적용 확인 후 BLOCK·RECORD·반복 접근·일반 YouTube 허용·Shorts/SPA 제한을 대조한다. 요청 ID는 UI·Worker·intent·HTTP 멱등키가 동일해야 한다.
5. 정상 END·정책 복원·로컬/DB 의무·접근 기록·통계 정합성을 확인한다. START/END가 미확정이면 같은 실행의 재요청·Cleanup·복구를 하지 않고 증거를 보존한다.
