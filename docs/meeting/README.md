# 회의록

## 목적

본 문서는 프로젝트 진행 과정에서 이루어진 회의 내용을 기록하고 관리하기 위한 문서입니다.

회의에서 논의한 내용, 결정 사항, 담당 업무 및 후속 작업을 체계적으로 관리하여 프로젝트 진행 과정과 의사결정 이력을 추적할 수 있도록 합니다.

---

## 현재 상태

현재 프로젝트는 아이디어 기획 및 선정 단계입니다.

아직 회의록은 작성되지 않았으며, 본 문서는 향후 사용할 회의록 작성 규칙과 템플릿을 정의합니다.

---

## 회의록 작성 원칙

모든 회의록은 아래 원칙을 기준으로 작성합니다.

- 가능한 한 회의가 종료된 당일 작성합니다.
- 회의 목적과 참석자를 반드시 기록합니다.
- 논의 내용과 최종 결정 사항을 구분하여 작성합니다.
- 담당 업무가 있는 경우 담당자와 목표 완료일을 함께 작성합니다.
- 회의록은 삭제하지 않고 프로젝트 종료 시까지 누적 관리합니다.
- 중요한 의사결정이 변경된 경우 변경 이유를 함께 기록합니다.

## 저장 위치

회의록은 아래 위치에서 관리합니다.

```text
docs/
└── meeting/
    ├── README.md
    ├── 2026-08-01-github-setup.md
    ├── 2026-08-05-idea-review.md
    └── ...
```

---

## 파일명 규칙

회의록은 다음 형식을 사용합니다.

```text
YYYY-MM-DD-회의주제.md
```

예시

```text
2026-08-01-github-setup.md
2026-08-05-idea-review.md
2026-08-12-role-assignment.md
```

같은 날 여러 번 회의를 진행하는 경우에도 회의 주제를 포함하여 파일명을 작성합니다.

## 관리 규칙

회의록은 프로젝트의 공식 기록으로 관리합니다.

- 회의 종료 후 가능한 한 당일 작성합니다.
- 결정 사항은 추후 확인할 수 있도록 명확하게 작성합니다.
- 담당 업무는 다음 회의에서 진행 여부를 확인합니다.
- 완료된 업무도 삭제하지 않고 진행 상태만 변경합니다.
- 기존 회의록은 삭제하지 않고 필요한 경우 수정 이력을 남깁니다.
- 프로젝트와 관계없는 개인 메모는 포함하지 않습니다.

- 의사결정 기록
- 일정 관리 방식
- 회고(Review) 기록
- 프로젝트 주요 마일스톤
