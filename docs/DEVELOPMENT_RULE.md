# 개발 규칙

본 문서는 프로젝트의 개발 구조와 기본 개발 원칙을 정의합니다.

현재 작성된 백엔드 계층 구조는 Spring 기반 개발을 가정한 초안이며, 프로젝트 주제와 기술 스택이 확정된 후 팀원 간 협의를 통해 수정할 수 있습니다.

---

## 백엔드 계층 구조

Spring 기반 백엔드를 사용할 경우 다음과 같은 계층 구조를 기본으로 합니다.

```text
Controller
    ↓
Service
    ↓
Repository
```

각 계층의 역할을 명확하게 분리하고, 한 계층이 다른 계층의 책임을 대신하지 않도록 합니다.

---

## 계층별 역할

### Controller

- 클라이언트의 요청(Request)을 받습니다.
- 요청 형식의 유효성 검사를 수행합니다.
- Service를 호출하여 처리 결과를 전달받습니다.
- 클라이언트에게 HTTP 응답(Response)을 반환합니다.
- 핵심 비즈니스 로직을 작성하지 않습니다.
- Database에 직접 접근하지 않습니다.

---

### Service

- 프로젝트의 핵심 비즈니스 로직을 담당합니다.
- 필요한 Repository를 호출합니다.
- 하나의 기능을 처리하기 위해 여러 Repository를 조합할 수 있습니다.
- 데이터 접근이 필요한 경우 Repository를 통해 처리합니다.
- HTTP 요청 및 응답 처리 코드를 작성하지 않습니다.

---

### Repository

- Database와 직접 통신합니다.
- 데이터의 조회, 저장, 수정, 삭제 작업을 수행합니다.
- 데이터 접근 로직만 담당합니다.
- 핵심 비즈니스 로직을 포함하지 않습니다.

---

## 기본 개발 원칙

프로젝트에서는 다음 원칙을 준수합니다.

- Controller에는 핵심 비즈니스 로직을 작성하지 않습니다.
- Controller에서 Repository를 직접 호출하지 않습니다.
- Service는 하나의 명확한 책임을 가지도록 작성합니다.
- Repository는 데이터 접근만 담당합니다.
- 각 계층의 역할과 책임을 명확하게 구분합니다.
- 공통 기능은 재사용 가능한 형태로 구현합니다.
- 중복 코드를 최소화합니다.
- 의미를 파악하기 어려운 이름은 사용하지 않습니다.
- 하나의 메서드가 지나치게 많은 작업을 처리하지 않도록 분리합니다.

---

## 백엔드 폴더 구조

Spring 기반 백엔드를 사용할 경우 다음과 같은 구조를 기본으로 합니다.

```text
backend/
├── controller/       # 요청 및 응답 처리
├── service/          # 비즈니스 로직
├── repository/       # 데이터 접근
├── entity/           # Database 테이블과 연결되는 객체
├── dto/              # 계층 간 데이터 전달 객체
├── config/           # 프로젝트 설정
└── exception/        # 예외 처리
```

실제 패키지 구조는 프로젝트 주제와 기술 스택이 확정된 후 변경할 수 있습니다.

- 예외 처리 규칙
- 입력값 검증 규칙
- Logging 규칙
- Test 작성 규칙
- Security 규칙
- API 응답 형식
