# 개발 기준

기능별 화면·동작·API 또는 로컬 처리·데이터·검증 기준은 [현행 설계](design/00_문서안내.md)를 따른다. 설계 변경이 필요하면 변경 이유와 영향 범위를 합의하고 관련 명세와 검증 기준을 함께 갱신한다.

## 작업과 완료

1. 해당 기능의 작업카드에서 담당·현재 상태·관련 명세를 확인한다.
2. 기능 단위로 구현하고 관련 검증 기준에 따라 확인한다.
3. 코드 위치·실행한 검증·결과·남은 문제를 작업카드에 기록한다.
4. PR 검토와 필요한 실제 연동 확인을 거쳐 완료 상태를 갱신한다.

구현 완료, 모의 응답 검증, 실제 연동 검증을 구분한다. 실행하지 못한 검증은 이유와 함께 미검증으로 남긴다. 기능 생략이나 임의 성공 처리로 완료 상태를 맞추지 않는다.

세부 절차와 단계별 완료 조건은 [개발 운영](implementation/개발운영.md), AI 작업 지침은 [AGENTS.md](../AGENTS.md), 브랜치·PR 규칙은 [기여 규칙](../CONTRIBUTING.md)을 따른다. 중복된 규칙을 별도로 관리하지 않는다.

## 후속 PC 확장

필수·추가 MVP 완료·검증 후 PC 앱으로 확장하여 PC 프로그램 관리 기능을 개발한다. 현재 상세 설계는 Web·Server·Chrome Extension 기준이며 모바일은 미정이다. PC 세부 설계·일정·담당은 후속 단계에서 구체화한다. 기존 47개 기능과 3인 담당 배정은 유지한다.

[개발 단계와 PC 후속 확장 계획](design/02_시스템_테크설계/09_PC_후속확장계획.md)을 함께 확인한다.
