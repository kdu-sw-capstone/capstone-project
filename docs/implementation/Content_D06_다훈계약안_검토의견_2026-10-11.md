## 3. 기존 종민 협의와 유지되는 부분

- Core 정책선택/문맥/탐색ID/DNR/Journal/이벤트/보고, Content frozen DOM 제한·복원/관찰, Server 검증·저장 책임 유지.
- 가장 구체 호스트 **전체 행** 사용, 부모 flags 혼합 금지. 임의 xxx.naver.com도 개별 설정 가능하며 치지직 특별 예외 없음. 세션 중 변경은 다음 세션.
- transport OK/SUPPORTED/changed만으로 전체 APPLIED/접근 확정 금지. 실제 효과, 캐시 최초 응답, 최신 QUERY 구분.
- 즉시 제한/한 접근 한 원문/확인된 복수 사유/late 원문 불변 유지. 실제 방문host와 정책host 분리.
- 한 문서 비회원 제어를 먼저 검증하자는 방향 유지. 다만 다훈 G-01의 착수 조건은 §5처럼 세 명에게 재확인하며 우리 판단으로 승인 범위를 줄이지 않는다.

## 4. 정확한 수정 예시 — 부분 객체, 신규 계약 아님

U-04: 회원 Snapshot의 선택행 site_id가 "42"인 경우의 policy 일부와 내부 논리 키 후보다. 전체 요청은 원본 envelope/context를 유지한다. Guest 사이트ID를 이 숫자로 강제하지 않는다. site_id source/type은 Core가 검증하며 Content가 Number 변환하지 않는다.

```json

  "viewer_count": 1,
  "hidden_viewer_count": 1,
  "inert_viewer_count": 1,
  "media_count": 1,
  "paused_media_count": 1,
  "observer_ready": true
}
```

U-06 키 예시: 같은 탐색·round의 서로 다른 kind 관찰은 다른 ID다. 아래는 두 관찰의 **부분 객체**이며 완전 메시지/접근 성공 증거가 아니다. context/navigation_id는 Core가 부여하고 observation_id만 Content가 생성한다. Event는 한 Core draft로 결합한다. round 필드명을 양쪽 observation.round_id로 통일하는 대안을 제안하며 별도 승인 필요.

```json
    "observation_id": "99999999-9999-4999-8999-999999999999",
    "observation": {"round_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa"},
    "navigation_id": "55555555-5555-4555-8555-555555555555"
  },
  "access_candidate": {
    "observation_id": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb",
    "observation": {"round_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa"},

```

U-02 ACK는 최초 accepted/disposition 데이터 불변 재응답을 권장한다. 같은 원문 재전송 때 새로운 DUPLICATE disposition으로 바꾸지 않고 현재 request_id로 감싼다. 첫 수용 후 freeze됐어도 과거 ACK는 현재 효과나 새 이벤트 수용 권한이 아니며 Core가 별도 현재 scope를 검증한다. stale/late 새 observation은 최초부터 해당 disposition으로 기록한다.

## 6. 역할과 다음 행동

1. 다훈: U별 수정안을 취합해 특히 U04 회원/Guest site_id·내부키, U03 runtime보고, U06 RECORD/freeze, G-01 단계별 예외를 최종 승인안에 반영/회신.
2. 종민: 미결속 QUERY document/instance·registry/해제 capacity·Snapshot false/whole검증·CRLF 결함 수정 근거 확인. Core 후속코드 SHA 고정. 이번 Content가 대신 수정하지 않음.
3. 지민: 승인 후 bootstrap/adapter·seq/cache·viewer/media/coverage·소유 복원·lifecycle 증거를 구현. 지금은 문서 의견만, 제품 listener/발신 없음.
4. 세 명: 승인 문서 해시/SHA·일시·profile·예외 표 기록 후 A 범위 착수. U전체 일괄 확정을 기다릴지 단계별 예외를 허용할지는 합의 사항이다. 이전 단독 ‘수락’을 공동 승인으로 올리지 않음.

## 7. 검증·미검증·게시 상태
