# 종민 전달용 — 기존 재검토와 다훈 계약안 검토 통합

2026-10-11 / 채지민 / 사용자 확인 후 게시하는 전달문. 이전 전달문 대신 이 문서를 사용한다. 기존 검토 이력은 삭제하지 않는다.

종민아, 기존 Core 재응답 검토와 다훈이가 보내준 D-06 문서 3개 검토를 합쳐서 전달할게.

## 우리가 한 일과 현재 상태

- Shorts 독립 제어와 시험 도구는 구현돼 있어. 과거 자동 33개는 합성 DOM·모의 정책 검증이고, 실제 YouTube 6단계는 사용자 실행 정상 보고야. 이번에 다시 실행한 결과는 아니야.
- 네 재응답을 검토한 문서는 c0a167410e82091e26d8f2f0e995e7702b32d7de까지 Push돼 있어.
- 다훈 문서 3개는 U-01~U-08별로 적용 가능한 원칙, 수정 제안, 테스트·추가 합의 항목을 나눠 검토했어. 이번 검토는 공동 승인 전 제안이며 아래 자료로 확인해 줘.
- 제품 Core↔Content listener·발신은 아직 구현하지 않았고, 신규 기능 테스트·제품 Chrome·Server 통합 테스트도 이번에 실행하지 않았어. 추가 MVP 코드와 PR #17·#21은 보존했고 develop 병합은 안 했어.

## 유지할 방향

Core 주입 확인→문서 QUERY→정책 push, 최초 명령 응답과 최신 QUERY 분리, 실제 DOM 효과와 소유 변경 복원 확인이라는 방향은 유지하자. Content의 SUPPORTED/changed나 메시지 전달 성공만으로 세션 적용 성공·접근 이벤트를 확정하지 않는 것도 같아.

Core는 정책·문맥·navigation_id·집계·이벤트·보고, Content는 frozen 정책의 DOM 적용·복원과 관찰 사실을 담당해. 가장 구체적인 호스트의 전체 정책 행만 적용하고 부모 flags를 섞지 않아. xxx.naver.com도 개별 정책 대상이고 세션 중 설정 변경은 다음 세션 적용이야.

## 종민이가 회신해 줬으면 하는 내용

각 항목에 **수락 / 수정안 / 보류, 코드 위치와 기준 SHA, 이유**를 적어줘. 현재 코드에 없으면 구현 예정으로 구분해 줘.

| 번호 | 확인·회신 요청 |
|---|---|
| U-01 | 미결속 QUERY의 문서/instance 결속 방식과 null owner/context 조회의 최소 응답 범위. 이미 결속된 정책·세션·current_result가 null QUERY로 노출되지 않게 하는 안 |
| U-02 | 최초 ACK 데이터 불변과 DUPLICATE 표기 충돌 해결, 완료 캐시와 high-water/활성/cleanup 기록 분리, 포화 시 RELEASE 보장. 16KiB·64·256·3초·10초는 미확정 시험값으로 유지 |
| U-03 | 필수 문서 집합·generation·coverage·부분 실패 집계. 회원 RUNNING 중 runtime fault는 기존 Server 보고로 처리 가능하다고 가정하지 말고 다훈에게 정확한 처리 경로 확인 |
| U-04 | 회원 site_id가 숫자 문자열인 실제 Snapshot과 UUID 예시 충돌 수정. Guest ID 규칙·논리 rule_id·무매칭/비활성 의미 확정. Content는 선택된 ID를 echo하고 DNR ID는 발급하지 않음 |
| U-05 | viewer 전체 hidden/inert, media 전체 paused, observer 준비의 증거 필드와 해제 후 잔존 검사. media 없는 viewer는 첫 범위 APPLIED로 인정하지 않는 방향 |
| U-06 | FEATURE_RESULT와 접근 후보에 서로 다른 observation_id를 쓰고 같은 navigation/round/rule로 결합하는 안. round 필드명 통일, freeze/late/RECORD는 다훈 포함 승인 |
| U-07 | 자동 item/query/fragment 이동을 새 접근으로 세지 않는 방향. 사용자 명시 탐색으로 인정할 증거와 경계는 추가 합의 |
| U-08 | BFCache INACTIVE와 GONE 구분, 재활성 전 보호·재결속, 기존 binding의 복원 의무와 응답 유실 처리. 실제 Chrome 실험 필요 |

별도 Core 결함 F-17-01~03의 수정 SHA·검증 근거도 알려줘. 이번 검토에서 해결됐다고 판정하지 않았어.

## 다훈 포함 세 명이 결정할 것

U-03 회원 runtime 보고/구간 처리, U-04 회원·Guest ID 규칙, U-06 이벤트 freeze/RECORD/관찰 키, U-07 접근 경계, U-08 수명·집계 기준은 다훈과 함께 확정하자.

다훈 체크리스트는 U 전체 승인 전 착수 금지와 작은 Guest 단위 우선 진행을 함께 적고 있어서 단계별 승인 범위를 명확히 해야 해. 한 문서 제어 시험만 먼저 할 수 있는지 세 명이 승인하고, 이벤트·회원 기능을 제외하는 범위를 기록하자. 지금 우리가 임의로 예외를 승인한 것은 아니야.

## 승인 후 첫 구현·검증

비회원·Shorts 한 정책·지원 top-frame 한 활성 문서에서 주입→QUERY→APPLY 실제 숨김/정지→RELEASE 복원을 먼저 검증하는 안이야. 이 단계에서는 접근 이벤트를 생성하지 않아.

모의 메시지/문맥·중복·오래된 명령·실패 테스트→Chrome 합성 DOM→실제 제품 YouTube 적용·해제 순서로 진행하자. 제품 Guest Snapshot·기존/새 탭·SPA·BFCache·이벤트·회원 Server 시험은 각각 별도이며 첫 단위 성공으로 전체 D06-T01~28을 통과 처리하지 않아.
