# 개발 운영

## 범위와 일정

Web·Server·Chrome Extension의 필수 MVP 및 추가 MVP 전체를 포함한다. PC 데스크톱은 이 패키지 범위 밖이다. 2027년 2월까지 개발을 목표로 하며 이후 종합 테스트·안정화를 진행한다. 개발 중 단위·통합 검증을 병행한다. 일일 참석·일일 완료를 요구하지 않는다. 작업은 각자의 가용 시간에 진행하며 단계 통과는 검증 결과로 판정한다. 목표일 경과가 단계 완료를 뜻하지 않는다.

## 준비

기존 3인 배정 확인 → 실행 저장소·실행 방법 확인 → 개발 환경과 비밀을 제외한 설정 예시 준비 → 설계의 API·이벤트·상태 형식 공유 → 작업카드 선택. 현황에는 개인 이름을 임의 기입하지 않는다.

## 1단계: 필수 MVP

첫 연동 목표는 사이트 설정 → 집중 시작 → 실제 차단 적용 확인 → 상태 조회 → 종료·해제 확인이다. SITE-02, POLICY-01, SESSION-01~04, EXT-01~02 및 필요한 AUTH 흐름을 연결한다. 회원 인증·설치 연결 등 선행 계약이 필요하면 함께 먼저 구현한다. 비회원 경로를 먼저 구현해도 회원 경로의 완료를 대신하지 않는다.

그 뒤 회원·비회원·자료 가져오기, 사이트 관리·Shorts, 이벤트 전송·반복 계산, 기록·통계·화면 설정을 완성한다. 이는 권장 진행 순서이며 미참여 인원을 기다리며 모든 독립 작업을 중단할 필요는 없다. 선행 API 미완성 시 합의된 응답으로 화면 개발을 진행할 수 있으나 실제 연동은 미검증으로 남긴다.

필수 단계 통과: 필수 33개 기능의 구현과 관련 수용 기준 검증, Web↔Server↔Extension의 실제 연동, 회원/비회원 경로, 필수 범위 오류·중복·저장·재시작 복구를 확인한다. 적용 가능한 경계 사례 중 실패·미검증이 남으면 통과로 표시하지 않는다.

## 2단계: 추가 MVP

추가 14개 기능 전부를 포함한다. 내부 기능 제한·키워드·성인 사이트·블러, 예약·일시정지·메모, 이용 시간·지표·시간대·AI 피드백을 기능별로 연결한다. 이용 시간·지표의 저장과 집계 기준이 준비된 후 해당 결과를 쓰는 분석·AI 경로를 검증한다. 화면·모델·연동 준비는 충돌 없는 범위에서 병행 가능하다.

추가 단계 통과: 추가 기능 수용 기준과 관련 경계 사례, 필수 기능 회귀 검증, 전체 상태·정책·저장·계정 전환의 실제 연동을 통과한다. 모의 응답·미실행 모델·미지원 환경을 실제 성공으로 표시하지 않는다.

## 작업 상태

미착수 → 진행 중 → 검토 대기 → 통합 대기 → 검증완료. 중간 상태로 중단·차단을 사용한다. 중단은 시간을 낼 수 없어 멈춘 경우, 차단은 선행 작업·명세 충돌 등 해결 조건이 있는 경우다. 검토 대기와 통합 대기는 완료가 아니다.

작업 시작 시 담당·브랜치·기준 커밋을 남기고, 중단 시 재개에 필요한 파일·명령·문제를 기록한다. 다음 작업자는 기록을 읽고 현재 코드와 대조한다. 같은 기능을 나누면 작업카드의 Web/Server/Extension 영역별 현황을 사용한다.

## 통합 시점

고정된 매일 회의 대신 준비된 PR을 통합 담당이 가능한 시간에 확인한다. 기능마다 전 영역을 한 PR에 넣을 필요는 없지만 실제 연결 전까지 기능 전체는 검증완료가 아니다. 첫 실제 연동을 모든 필수 기능 완성 시점까지 미루지 않는다.

통합 담당 AI는 기준 커밋과 PR 변경을 확인하고 API·소유권·상태·데이터 계약 차이를 기록한다. 충돌이 없는 수정은 검증과 함께 진행하며 설계 변경은 합의와 기록을 먼저 남긴다. 병합 전 관련 자동 테스트 및 필요한 브라우저·확장 수동 확인을 수행한다. 미실행 항목이 있으면 원인과 실행 담당을 기록한다.

## 기록 원칙

각 기능 작업카드가 해당 기능의 상세 작업·검증 기록 원본이다. 통합현황.md는 그 상태를 요약한다. 설계연결.json은 설계 참조 원본이며 구현 현황을 기록하려고 원래 설계 ID를 바꾸지 않는다. 동일 API가 여러 기능에 연결되므로 API 수만으로 기능 완료를 계산하지 않는다.
