# 실행 엔진 선택적 재구축 검토 · 2026-10-28

판정: **B안의 단계적 분리 실험을 선택한다. 전체 엔진 교체 및 실제 수용 완료 판정은 보류한다.**

브랜치: `codex/execution-engine-review-20261028`

기준: 기존 통합 작업 공간의 미커밋 최신 소스를 파일별 SHA로 복사했다. HEAD만 복사하면 최신 수정이 누락되므로 `ENGINE-BASELINE.json`에 복사 기준을 기록했다. 기존 작업 공간·index·실제 설치는 변경하지 않았다. Commit/Push/PR/Merge는 수행하지 않았다.

## 분석 근거와 한계

- `extension/a1/core.mjs`: 약 68KB, Session·Snapshot·Native census·재검증·Binding·END·복원을 한 클래스에서 처리한다. `serial`, `tick`, `reconcile`, `navigation`, `nrBegin`, `finish`가 동일 인스턴스의 상태와 저장소에 결속돼 있다.
- `extension/member-a1/core.mjs`: 약 90KB. 비회원 Core와 비슷한 역할에 회원 승인·서버 확인 보고·문서 retirement가 추가된다. 같은 모양이라고 동일 계약은 아니므로 두 파일을 단순 합치지 않는다.
- 두 `entry.mjs`에서 탐색·준비·완료·history 이벤트를 각자 연결한다. 문서 이벤트 조정은 공유 가능한 경계다.
- `a1/content.mjs`, `member-a1/content.mjs`: 작업 ID·fingerprint·BEGIN·최초 응답 보존·scope 검사를 수행한다. 단순 DOM 제어기와 교체하면 기존 멱등성과 원장 계약을 잃는다.
- `a0/shorts-effect.mjs`, `content/shorts.mjs`: 실제 DOM 변경·미디어 정지·안내·복원·효과 측정 계층이다. Root 준비 상태와 Content 효과 ACK는 서로 대체할 수 없다.
- `a1/registry.mjs`, `p1.mjs`, `store.mjs`: 문서/소유권·세대·원자 쓰기·Native proof 검증이 결속돼 있다. 이를 떼어 새 저장소를 만드는 방식은 최소 재구축이 아니다.
- 최신 실패의 `USER_OPERATION_UNCONFIRMED`는 최초 Core 오류 코드가 아니다. 후속 `PRODUCT_CHANNEL_CLOSED` 기록만으로 검색 Shorts 실패 원인을 확정할 수 없다. 이번 구조 분석이 개별 실패의 직접 원인을 증명하지는 않는다.

## 실제 구현 범위

1. `execution/document-lifecycle.mjs`: Root 이벤트를 문서별로 구분한다. 오래된/다른 문서 준비 이벤트는 현재 문서를 바꾸지 않는다. BEFORE만으로 소멸을 추정하지 않는다. 교체/탭 종료 관측을 Binding 삭제 또는 복원 완료로 승격하지 않는다.
2. `execution/document-coordinator.mjs`: 회원·비회원 공통 이벤트 큐. 동일한 대기 이벤트만 합치고 완료된 결과를 증거로 재사용하지 않는다. 임의 예약 지연은 추가하지 않는다. 실패를 기록하고 자동 재시도하지 않는다. 새 세션·원장·END 경로는 없다.
3. 두 `entry.mjs`: **신뢰된 env의 `experimentalDocumentCoordinator === true`일 때만** 공통 조정 계층을 사용한다. 기본 생성 엔트리는 이 옵션을 설정하지 않는다. 메시지·Storage 값으로 실험 모드를 켤 수 없다.
4. 두 build script 및 생성 Worker bundle: 공통 모듈을 포함한다. Content bundle과 공용 계약·Core 본체는 원본과 동일하다.
5. `tests/document-coordinator.test.mjs`: 독립 모델 검사와 실제 회원·비회원 Core census 호출을 포함한다.

새 조정 계층의 map은 일시적인 Root 관측 자료다. 실행·복구·해제 권한은 기존 Core 저장소에만 있다. Worker 재생성 때 이 map이 비어 있는 것을 정상 실행 또는 소멸 증거로 해석하지 않는다.

## 남은 차단 조건과 다음 판단

이 단계는 **실행 엔진 전체의 대체 구현이 아니다**. 다음 사항이 남아 있어 실제 최종 수용 후보로 제시하지 않는다.

### 새로 확보한 독립 반례

`ENGINE-SPA-COUNTEREXAMPLE.json`: 같은 documentId에서 Native frame URL과 메시지 sender URL을 SPA 이후 URL로 함께 바꾼 fixture에서, 기존 Core와 새 조정 계층 모두 `CLEANUP_REQUIRED`(cause `UNAUTHORIZED_SENDER`) → UNKNOWN, 미해소 Binding 1건을 남겼다. 원본과 동일 입력으로 비교했다.

호출 경계는 `member-a1/core.mjs::cleanupInactiveOnce`의 기존 release → `member-a1/p1.mjs`의 재검증이다. 기존 proof의 `sender_url_sha256`과 현재 응답의 URL 해시가 다르면 line 70의 불변 proof 검사가 거절한다. `admission`에도 별도의 동일 URL 검사가 있다. 따라서 단순 listener 통합만으로 이 반례는 해결되지 않는다.

이것은 **실제 브라우저에서 sender.url이 언제 갱신됐는지 확인한 증거가 아니다**. 역사 Chrome 실패의 직접 원인으로 승격하지 않는다. Chrome의 [MessageSender 계약](https://developer.chrome.com/docs/extensions/reference/api/runtime#type-MessageSender)은 sender URL과 documentId를 별도 값으로 제공하지만 이번 기존 fixture는 원래 sender URL을 기본적으로 고정한다. 변동 조건을 따로 시험해야 한다.

다음 재구축 경계는 **동일 문서의 경로 변화와 불변 문서/작업 신원을 분리하는 정식 인계**다. 기존 sender URL 검사를 삭제하거나 proof 값을 덮어써 PASS시키지 않는다. 기존 적용·복원 작업의 권한과 새 경로의 재평가 권한을 구별하고, Root 관측·문서·Content 인스턴스·세션·세대·기존 원장을 결속하는 설계와 회귀가 먼저 필요하다. 이 인계 구현은 아직 완료하지 않았다.

1. 새 공통 라우터를 켠 상태의 Worker 재생성·END 우선순위·실제 영속 Core 통합 시험이 필요하다. 기존 기본 모드 회귀 PASS로 대신하지 않는다.
2. Core 내부 serial/reconcile 및 회원 보고 대기 책임은 남아 있다. 실제 지연 증거 없이 큐를 병렬화하거나 5초 기한을 바꾸지 않는다.
3. Content의 검색 결과 탐지·SPA 효과와 새 라우터의 결합은 실제 Chrome에서 검증하지 않았다. 현재 검색 Shorts 결함을 해결했다고 표시하지 않는다.
4. Native transport 관측과 정식 채널 종료/재연결 계약의 통합은 미완료다. 연결 관측 메서드만으로 재연결 지원을 주장하지 않는다.
5. 재기동·영속 원장·미해소 복원 의무·실제 DNR·서버 잠금까지 통과해야 기존 엔진을 대체할 수 있다.

독립 통합 범위가 완성되면 실험 플래그가 켜진 별도 후보 SHA를 먼저 고정한다. 그 후에만 별도 실제 설치/Chrome/START·END 승인과 현재 안전 게이트를 확보한다. 이번 검토 중에는 해당 실행이나 Git 게시를 수행하지 않는다.
