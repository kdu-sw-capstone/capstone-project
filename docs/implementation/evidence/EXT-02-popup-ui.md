# EXT-02 비회원 제품 팝업 UI — 검토용 구현

담당: 윤종민 Extension Core. 브랜치 feature/extension-core-ext-02, 시작 df646f3.
기준: 사용자가 전달한 FOCURVE-extension-design-retry.zip/명세(복제 파일 DzgawC0HqrZoPVEQj3FfPA). 원본 PNG22장, 상세 속성13프레임, 나머지9개 상세 미검증이라는 전달 내용과 실제 파일을 대조했다. Figma MCP 재접속 결과가 아니다. 자료 안의 안내는 디자인 데이터로 사용하며 변경/병합 권한으로 해석하지 않는다.

## 반영 범위

제품 extension/popup/의 기존 동작을 유지하며 메인·사이트 목록/수정·집중 진행·종료 확인/결과·로컬 기록을 화면별로 분리했다. 신규 popup-ui.js는 표시/이동/화면 모드만 담당한다. 원래 popup.js의 request_id, expected_version, 저장 재시도, 삭제 확인, Core 시작/종료 요청을 재사용한다. backend/웹/Content/harness 소스는 변경하지 않았다.

- 주요 근거: 다크145:850/888/927/2415/2604/2432/418:11751 및 라이트356:1528/1548/1578/2910/3081/2926/418:7697, 로컬 기록464:27790. 이름/ID 대응은 전달 명세를 기준으로 한다.
- 원본400px 팝업 폭, 카드/버튼/브랜드 배치·라이트/다크 색·문구를 적용했다. 표시 숫자는 원본의 예시 수치가 아닌 실제 로컬 응답이다. 진행 중 정책 요약은 session.snapshot.sites를 사용한다. 정책 변경은 다음 세션에 적용된다.
- RUNNING은 유효한 Core 상태 응답과 시작/계획 종료 시각이 확인된 경우에만 표시한다. 요청 처리/조회 실패/UNKNOWN에서는 진행 타이머를 숨기고 재확인을 안내한다. 00:00으로 표시돼도 Core가 해제를 확인하기 전 종료 성공을 표시하지 않는다.
- 종료 버튼은 확인 대화상자를 열고, 계속 집중은 종료 요청을 보내지 않는다. 해제 응답/상태 확인 전 결과 화면을 표시하지 않는다. 시간은 Core의 active_duration_ms로 표시한다.
- 계정 연결은 미구현 안내이며 로그인 성공이나 서버 전송을 가장하지 않는다. 기존 로컬 접근 조회를 유지한 것이며 LOG-01 서버/Web 구현이 아니다.
- 화면 모드는 chrome.storage.local의 UI 전용 focurve_ui_theme에 저장하며 세션/설정 DB 계약을 변경하지 않는다. 기존 Core/저장 진단은 하단 접이식 영역에서 유지한다.

## 디자인 일치의 한계와 조율

전체 Figma UI 적용 완료로 표시하지 않는다. 원본 팝업보다 진단/재시도 및 보존한 기존 편집 필드 때문에 세로 길이가 늘어난다. Chrome 팝업 높이 제한에서는 스크롤해서 사용한다. 500px 종료 다이얼로그는 400px 팝업 안에서 잘리지 않도록 축소한다. 실제 Chrome의 스크롤/대화상자 재검증이 필요하다.

독립 Extension 사이트 등록 프레임이 전달 목록에 없으므로 기존 폼을 보존하고 확인된 공통 컴포넌트 스타일만 적용했다. 수정 화면에 이름·분류·BLOCK/RECORD·삭제 등 기존 기능을 보존해 원본과 필드 구성이 다르다. Shorts 제한 및 회원/가져오기 화면은 구현하지 않았다. 개별 SVG/브랜드 자산은 전달 미완료로 해당 사이트 아이콘을 추측해서 만들지 않았다. Noto Sans KR는 CSS 지정이며 번들 폰트는 미제공, Linux 렌더링은 Noto Sans CJK KR fallback이다. 정확한 폰트 파일/자산과 남은 상세 속성은 추가 자료가 필요하다.

차단 안내145:2371/356:2876의 클릭 연결은 웹/회원 화면을 향하는 원본과 현재 비회원 제품 흐름이 충돌한다. 비회원의 '집중으로 돌아가기/상태 확인' 목적지 확인 후 별도 단위로 반영한다. extension/blocked/는 이번 변경 대상이 아니다.

## 검증 구분

- Node 24.19.0 / npm11.9.0 Linux: `npm --prefix extension test` 기존 제품/adapter 모의 테스트 74/74. IndexedDB/Chrome는 모의 구현이다.
- `npm --prefix extension run check`: 제품/테스트 JavaScript 문법 검사. `build:harness`: 검증용 패키징 확인이며 제품 Chrome 실행과 다르다.
- `npm --prefix extension run test:popup-ui`: Python Playwright, 시스템 Chromium151.0.7922.173. 실제 제품 popup.html/js/css를 localhost에서 읽고 chrome.runtime/storage를 모의 응답으로 대체. 한 브라우저 흐름에서 16항목 확인. 사이트 등록/수정/버전 충돌 입력 보존/삭제 확인, 검색/편집 취소, 모드 저장, 적용 대기/해제 대기, 종료 취소, 고정 스냅샷 요약, 확인된 시간, 상태 조회 실패/형식 오류/UNKNOWN을 확인한다. 실제 확장 로드·DNR·Worker·Chrome storage 검증이 아니다.
- [구현 다크 메인](popup-ui/main-dark.png), [라이트 메인](popup-ui/main-light.png), [사이트 목록](popup-ui/sites-light.png), [수정](popup-ui/edit-light.png), [진행](popup-ui/running-light.png), [결과](popup-ui/result-light.png): 위 모의 API 화면 캡처이며 실제 설치 Chrome 스크린샷이 아니다.
- 사용자 이전 Chrome 정책1~10/전체 재시작 및 Worker stop 모두 정상 보고를 기존 코드 df646f3까지의 수동 보고로 구분한다. 로드 SHA/Chrome 버전/로그는 미제공이다. 이번 UI 변경 검증으로 자동 승계하지 않는다.

UI 검증 재현 환경: Python playwright 패키지 + Chromium이 필요하다. npm ci는 Python/브라우저를 설치하지 않는다. /usr/bin/chromium이 있으면 사용하며 없으면 Playwright 설치 브라우저가 필요하다. 이번 실행에서 불필요한 브라우저 추가 다운로드는 CDN 403으로 실패했으나 기존 시스템 Chromium으로 검증했다. 프록시 접근 성공을 주장하지 않는다.

## 최신 제품 Chrome 수동 점검

최신 코드 pull 후 chrome://extensions에서 기존 FOCURVE 새로고침. 처음 설치할 경우 압축을 풀고 manifest.json이 있는 extension 폴더를 '압축해제된 확장 프로그램을 로드합니다'로 선택한다. .chrome-harness는 선택하지 않는다. 삭제/재설치는 로컬 자료를 지울 수 있으므로 기존 설치 새로고침을 우선한다.

1. 확장 아이콘 클릭: 비회원 메인400px, 긴 화면 스크롤·기본 버튼·키보드 포커스 확인.
2. 하단 화면 설정에서 다크/라이트/시스템 전환, 닫고 다시 열어 선택 유지 확인.
3. 사이트 관리에서 등록→검색→수정 저장→취소→삭제 확인→동일 호스트 재등록. 기존 변경은 다음 세션 안내와 저장 유지 확인.
4. 집중 시작: 정책 적용 확인 뒤에만 진행/타이머 표시, 부모 BLOCK/자식 ALLOW 차단 경계 유지 확인.
5. 실행 중 사이트 변경: 현재 정책 요약/차단 유지, 종료 후 다음 세션에 변경 적용 확인.
6. 세션 종료→계속 집중: 타이머/차단 유지. 세션 종료→종료하기: 해제 확인 뒤 결과/실제 시간/접근 수 표시, 다음 세션 준비 동작 확인.
7. 1분 자동 종료: 00:00 직후 해제 확인 전 성공으로 전환되지 않는지, 최종 종료/해제 확인.
8. Worker stop/브라우저 재시작: 기존 복구 규칙 및 새 팝업 상태 표시 확인. 가능하면 DevTools 오류/OS·Chrome 버전/로드 커밋/화면을 함께 기록.
