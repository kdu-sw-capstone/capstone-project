- 공용 문서의 최신 SITE 규칙과 Server 미반영 상태를 함께 기록했다. schema_version1.1 유지의 필드 추가 수용/legacy 처리·FEATURE 상세는 Server 담당과 확인이 필요하다. 문서 작성이 Server 검증기 변경이나 HTTP 성공을 의미하지 않는다.

## 최신 로컬 제품 Chrome 수동 절차

이번 수정은 Push하지 않으므로 git pull만으로 받을 수 없다. 검증용 최신 ZIP을 사용하고 기존 확장의 디렉터리를 안전하게 교체/새로고침한다. 기존 설치 삭제/DB 삭제는 하지 않는다. manifest.json이 있는 extension 폴더를 사용하며 .chrome-harness는 사용하지 않는다. 1. naver.com을 하위 포함 RECORD로 등록하고 세션 시작.
2. chzzk.naver.com → www.naver.com → chzzk.naver.com → www.naver.com을 명시적으로 방문. 로컬 기록 전체4/반복2, 각 host 첫 접근 index1·재접근 index2. 사이트 실제 가용성/탐색 실패면 성공으로 계산하지 않고 실패 기록.
3. 팝업 Core 연결 확인에서 열린 Worker DevTools Application → IndexedDB → focurve-execution → events 원본을 확인. 신규 payload.target_key는 각각 SITE:chzzk.naver.com/SITE:www.naver.com, target_host 일치, matched_policy_host=naver.com. URL/path/query 원본을 이벤트에 저장하지 않는지 확인.
4. 종료/다음 세션에서 같은 host 첫 방문은 반복이 아니어야 한다. BLOCK으로 다음 세션 진행하면 같은 실제 host별 key·policy host를 저장하며 차단 안내 새로고침은 추가 접근이 아니어야 한다.

6. 자식 ALLOW/RECORD와 부모 BLOCK, 그 반대의 MOST_SPECIFIC_HOST 차단/허용 경계 및 현재 snapshot/다음 세션 변경 유지 확인.
