# Shorts 8영역 P0 통합 안정화

상태: 독립 후보 구현·검증 중. 브랜치 `codex/execution-engine-review-20261028`, 시작 HEAD `90ad32be5d282f3b44c917a29e156dffc5e29187`와 기존 실험 미커밋 소스. 기존 설치·다른 작업 공간·UNKNOWN·HOLD는 변경하지 않는다.

기준: POLICY-03 / EXT-02 / SESSION-01~02, TF-05~08, AC-POLICY-03-01~03, AC-SESSION-02-01~03. 최신 사용자 지시에 따라 8영역 모두 P0이며 한 영역의 자동 PASS를 전체 완료로 사용하지 않는다.

## 공통 원인과 수정 경계

동일 documentId의 URL 변경 시 기존 P1 pre-effect proof의 sender URL과 현재 sender URL이 달라질 수 있다. 기존 Core/조정 계층 모두 이 독립 반례에서 원래 RELEASE를 완료하지 못했다. 이 사실이 모든 역사 Chrome 실패의 직접 원인을 증명하지는 않는다. DOM 크기 검사·END 버튼·서버 보고 대기는 별도 결함이며 기존 수정과 회귀를 유지한다.

### 제한된 문서 인계 계약

- 신뢰된 Worker 환경의 기존 실험 플래그에서만 사용한다. 실제 제품 기본 경로는 변경하지 않는다.
- 같은 설치·프로필·Worker boot·회원/비회원 소유자·세션·documentId·Content 인스턴스·registration·credential·receiver SHA를 검증한다. Root의 현재 frame과 Content challenge 응답을 결속한다.
- 이미 열린 NR01 창, 동일 원래 proof 참조, INACTIVE/apply_closed Binding, 정확한 generation/fence와 기존 5초 기한 안에서만 인계 후보가 된다. UNKNOWN·FAILED·END·문서 교체·다른 origin은 거절한다.
- 원래 NATIVE_BINDING_PROOF 및 최초 작업 응답은 변경하지 않는다. 기존 boot 재검증 sidecar와 일시적인 challenge capability를 사용하며 새 영속 저장소·schema·복원 예산을 만들지 않는다.
- 새 capability는 원래 Binding의 제한된 관측과 기존 CLEANUP_ONLY RELEASE guard에만 진입한다. 새 APPLY/LEDGER_PLAN/CHECKPOINT/DOM_CONFIRM 권한이 아니다. 실제 RELEASE ACK·복원 증거가 있어야 기존 Binding이 해소된다. 새 경로의 적용은 기존 Core가 새 Binding/원래 정책 snapshot으로 별도 확인한다.
- Worker 재생성·generation 변경·기한 만료·응답 유실 시 capability를 재구성하지 않는다. 기존 의무를 보존한다. 반복 전환은 매번 현재 관측을 다시 수행하며 완료 결과를 새 증거로 재사용하지 않는다.

## 독립 후보에 반영한 확인된 결함

1. NR/DP/ND 설정은 실제 명령에도 표식이 있어야 한다. 이전 문서 조정 시험은 Core 옵션만 켜고 명령 표식과 epoch 시각을 빠뜨렸다. 원본 실패는 보존하고, 정식 표식·시각으로 동일 입력의 baseline 실패와 후보 성공을 비교했다.
2. 같은 문서 URL 변경: 기존 pre-effect proof의 URL을 덮어쓰지 않고, 현재 Root frame과 scoped Content challenge를 결속한 boot-local capability로 원래 CLEANUP_ONLY만 허용한다. unknown sender URL·다른 문서/설치/세대·기한 초과는 계속 거절한다.
3. 비회원 새로고침: 기존 회원 D1의 문서 retirement 구현을 비회원 계약으로 이식했다. 비회원 schema에는 기존 TAB_REMOVED 증거와 별개인 정확한 DOCUMENT_RETIRED 분기만 추가했고 replacement_document_id를 필수로 요구한다. 새 복구 엔진이나 증거 없는 GONE 전이를 만들지 않았다. 기존 비회원 경로는 실험 플래그가 꺼져 있으면 유지한다.
4. 반복 새로고침: 같은 밀리초의 이전 문서 COMMITTED를 새 replacement로 재사용하던 결함을 양쪽 D1에서 막았다. 처리 대상 원래 documentId와 같은 COMMITTED는 retirement 근거가 아니다.
5. 조정 계층: outgoing READY/HISTORY가 pending navigation을 지우지 못하게 했고, duplicate COMMITTED의 READY 강등과 BEFORE tab map 무한 증가를 막았다. fragment 변경도 기존 HISTORY 검증으로 연결한다.

검토 브랜치의 생성기는 실험 모드를 명시적으로 켠 번들을 기본 생성하며, `experimentalDocumentCoordinator:false` 호환 빌드도 검증한다. 기존 통합 작업 공간·실제 설치의 생성기는 변경하지 않았다. Content bundle의 모드별 차이는 없으며 Core/Content ACK·멱등성·복원 증거 검사는 유지한다.

최종 Extension 자동 회귀: **690/690 PASS**. 실제 DOM 객체·실제 Core/작업 원장 모듈을 함께 사용하는 모의 전송 시험에서 검색→Shorts→일반 영상→정상 END·DOM 복원, 회원/비회원 반복 URL 변경·새로고침·정상 END·DNR 해소·종료 자료 보존이 통과했다. 브라우저 API·네트워크·IndexedDB 엔진은 fixture이므로 실제 Chrome 또는 실제 Server/MySQL 수용으로 승격하지 않는다.
