# 팀 운영 가이드

본 문서는 캡스톤 프로젝트를 진행하는 팀의 운영 원칙, 역할 분담, 업무 관리 및 의사소통 기준을 정의합니다.

Git 작업 절차는 [Git 사용 가이드](./GIT_GUIDE.md), Git 협업 규칙은 [기여 가이드](../CONTRIBUTING.md)를 따릅니다.

---

## 팀 운영 원칙

프로젝트는 다음 원칙에 따라 운영합니다.

1. 작업 목적과 범위를 먼저 공유합니다.
2. 중요한 결정은 문서로 기록합니다.
3. 기능 개발과 문서 관리를 동일한 중요도로 관리합니다.
4. 문제는 가능한 한 빠르게 공유합니다.
5. 프로젝트 구조 변경은 팀원과 협의 후 진행합니다.
6. 일정 변경이 발생하면 즉시 공유합니다.
7. 실제 구현 내용과 문서를 항상 동일하게 유지합니다.

---

## 업무 분담

프로젝트 주제와 기술 스택이 확정되면 팀원별 담당 영역을 지정합니다.

예시

- 프로젝트 기획
- 프론트엔드
- 백엔드
- 데이터베이스
- 브라우저 확장 프로그램
- 테스트
- 배포
- 문서 관리
- 발표 준비

담당 영역은 책임 범위를 의미하며, 필요 시 다른 팀원이 함께 작업할 수 있습니다.

---

## 작업 관리

작업은 가능한 한 작은 단위로 나누어 관리합니다.

각 작업에는 다음 내용을 명확하게 정의합니다.

- 작업 목적
- 담당자
- 완료 기준
- 예상 일정
- 관련 문서

작업 완료 기준은 코드 작성이 아니라 다음 조건을 모두 만족한 시점입니다.

- 기능 구현 완료
- 필요한 테스트 완료
- 관련 문서 수정 완료
- Pull Request 병합 완료

---

## 의사소통

### 작업 시작 전

다음 내용을 팀원과 공유합니다.

- 작업 목적
- 작업 범위
- 수정 예정 파일
- 예상 일정

### 작업 진행 중

다음 상황에서는 즉시 공유합니다.

- 일정 지연
- 기능 변경
- 구조 변경
- 다른 작업과 충돌 가능성
- 도움이 필요한 사항

### 작업 완료 후

다음 내용을 공유합니다.

- 완료한 작업
- 주요 변경 사항
- 테스트 결과
- 확인이 필요한 사항

---

## 회의 운영

회의는 다음 순서로 진행합니다.

1. 이전 작업 진행 상황 확인
2. 문제 및 이슈 공유
3. 안건 논의
4. 의사결정
5. 담당 업무 지정
6. 다음 일정 확인

회의 결과는 반드시 회의록으로 작성합니다.

회의록 작성 규칙은 [회의록 관리](./meeting/README.md)를 참고합니다.

---

## 의사결정 기준

중요한 결정은 다음 기준을 우선합니다.

- 프로젝트 목표에 적합한가
- 일정 안에 구현 가능한가
- 유지보수가 가능한가
- 발표 및 시연이 가능한가
- 팀원이 이해할 수 있는 구조인가

개인 취향보다 프로젝트 목적과 유지보수성을 우선합니다.

---

## 문서 관리

프로젝트 문서는 실제 구현 상태와 동일하게 유지합니다.

다음과 같은 변경이 발생하면 관련 문서를 함께 수정합니다.

- 기능 변경
- 시스템 구조 변경
- API 변경
- 개발 규칙 변경
- 팀 운영 방식 변경

---

## 금지 사항

다음 행위는 원칙적으로 금지합니다.

- 중요한 변경 사항을 공유하지 않는 행위
- 문서 없이 의사결정을 진행하는 행위
- 실제 구현과 다른 내용을 문서에 작성하는 행위
- 일정 지연을 숨기는 행위
- 출처를 확인하지 않은 자료를 사용하는 행위
- 민감한 정보를 저장소에 포함하는 행위

Git 관련 금지 사항은 [기여 가이드](../CONTRIBUTING.md)를 따릅니다.
