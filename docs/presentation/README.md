# 발표 자료 관리

## 목적

본 문서는 프로젝트의 발표 자료와 발표 준비 과정을 체계적으로 관리하기 위한 기준 문서입니다.

제안 발표, 중간 발표, 최종 발표 등 프로젝트 진행 과정에서 작성되는 발표 자료를 일관된 방식으로 관리하고, 발표 내용과 실제 프로젝트 진행 상태가 항상 일치하도록 유지하는 것을 목적으로 합니다.

---

## 현재 상태

현재 프로젝트는 아이디어 기획 및 선정 단계입니다.

아직 발표 일정, 발표 형식 및 제출 기준이 확정되지 않았으므로 실제 발표 자료는 작성하지 않습니다.

현재 문서는 향후 발표 자료를 관리하기 위한 작성 기준과 템플릿을 정의합니다.

---

## 발표 자료 저장 위치

발표 자료는 다음 구조를 기준으로 관리합니다.

```text
docs/
└── presentation/
    ├── proposal/
    ├── midterm/
    ├── final/
    └── README.md
```

| 폴더 | 설명 |
|------|------|
| `proposal/` | 제안 및 기획 발표 자료 |
| `midterm/` | 중간 발표 자료 |
| `final/` | 최종 발표 및 시연 자료 |

프로젝트 진행 상황에 따라 필요한 폴더를 추가하거나 구조를 변경할 수 있습니다.

---

## 파일명 규칙

발표 자료는 다음 형식을 사용합니다.

```text
YYYY-MM-DD_발표구분_문서종류_버전
```

예시

```text
2026-09-10_제안발표_PPT_v1.pptx
2026-09-10_제안발표_발표대본_v1.md
2026-11-20_중간발표_PPT_v3.pptx
2027-05-15_최종발표_PDF_final.pdf
```

파일명은 영문, 숫자, 하이픈(-), 밑줄(_) 사용을 권장합니다.

---

## 버전 관리 규칙

발표 자료를 수정하는 경우 기존 파일을 임의로 덮어쓰기보다 버전을 구분하여 관리하는 것을 원칙으로 합니다.

예시

```text
v1
v2
v3
final
```

최종 제출본은 `final`을 사용합니다.

단, 사소한 오탈자 수정 등 별도의 버전 관리가 필요하지 않은 경우에는 기존 파일을 수정할 수 있습니다.

## 발표 자료 종류

프로젝트 진행 상황에 따라 다음 자료를 관리합니다.

- 발표용 PPT
- 제출용 PDF
- 발표 대본
- 예상 질문 및 답변
- 시연 순서
- 시연용 데이터
- 발표 피드백 문서
- 발표 결과 기록

필요한 자료만 작성하며 프로젝트 특성에 따라 추가할 수 있습니다.

## 발표 체크리스트

### 발표 자료

- [ ] 발표 목적이 명확한가
- [ ] 문제와 해결 방법이 자연스럽게 연결되는가
- [ ] 핵심 기능이 구체적으로 설명되는가
- [ ] 실제 구현 상태와 발표 내용이 일치하는가
- [ ] 오탈자와 잘못된 정보가 없는가
- [ ] 필요한 출처를 모두 표시했는가

### 시연

- [ ] 시연 기능이 정상적으로 동작하는가
- [ ] 시연용 계정과 데이터가 준비되었는가
- [ ] 예외 상황에 대비한 대체 자료가 있는가
- [ ] 시연 순서가 정리되어 있는가

### 발표 연습

- [ ] 제한 시간 안에 발표가 가능한가
- [ ] 팀원별 발표 범위가 정리되었는가
- [ ] 발표 전환이 자연스러운가
- [ ] 예상 질문을 준비했는가
- [ ] 최종 리허설을 완료했는가

---

## 문서 관리 규칙

- 발표 자료는 해당 발표 폴더에 저장합니다.
- 발표 자료를 수정한 경우 관련 문서도 함께 최신 상태로 유지합니다.
- 최종 제출본은 `final` 버전으로 관리합니다.
- 발표 내용과 실제 프로젝트 진행 상태가 일치하도록 확인합니다.
- 발표 종료 후 피드백을 반드시 기록합니다.
- 팀 공용 자료만 저장합니다.
- 용량이 큰 영상은 외부 저장소 링크를 사용합니다.
- API Key, 비밀번호, 개인정보 등 민감한 정보는 포함하지 않습니다.
