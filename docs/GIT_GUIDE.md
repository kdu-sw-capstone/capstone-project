# Git 작업 순서

## 브랜치

- main: 통합 검증을 통과한 안정 버전
- develop: 기능을 모아 연동하는 기준 브랜치
- 작업 브랜치: 최신 develop에서 기능·오류 수정·문서 작업 단위로 생성

브랜치 이름과 커밋 형식, PR 검토 규칙은 [기여 규칙](../CONTRIBUTING.md)을 따른다.

## 작업 시작과 재개

1. 저장소를 clone한 작업 폴더에서 현재 브랜치와 저장하지 않은 변경을 확인한다.
2. 새 작업은 기존 변경을 보존한 뒤 최신 develop에서 작업 브랜치를 만든다.
3. 이전 작업을 재개할 때는 해당 브랜치와 작업카드를 확인하고 develop의 변경을 반영한다.
4. 작업카드에 기능 ID·담당·브랜치·기준 커밋을 기록한다.

## 반영과 병합

1. 변경 내용과 관련 검증 결과를 확인한다. 다른 작업자의 수정과 비밀값이 포함되지 않았는지 점검한다.
2. 커밋하고 작업 브랜치를 push한다.
3. develop을 대상으로 PR을 만들고 기능 ID·설계 대응·검증 결과·미완료 항목을 적는다.
4. 다른 구성원의 검토를 거쳐 병합하고 실제 연동 결과를 작업카드와 통합 현황에 반영한다.
5. 병합된 작업 브랜치를 정리한다. 안정 버전은 develop에서 main으로 PR을 만들어 반영한다.

## ZIP으로 받은 자료 반영

다운로드한 ZIP 폴더에는 Git 이력이 없을 수 있다. 실제 저장소를 clone한 작업 폴더에서 문서 작업 브랜치를 만들고 파일 차이를 비교해 반영한다. 기존 코드나 다른 작업자의 변경을 일괄 덮어쓰지 않는다. 보관으로 이동한 파일은 이전 경로에 중복으로 남지 않도록 변경 목록에서 확인한다. 원격 이력을 대체하는 강제 push는 사용하지 않는다.
