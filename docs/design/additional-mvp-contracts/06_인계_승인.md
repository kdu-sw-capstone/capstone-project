공통 Schema/API/SQL 파일은 김다훈이 변경 조정자로 관리, Core scope/ACK/DNR 부분은 윤종민, Content effect/restore 부분은 채지민 승인 필요. 별도 feature branch에서 공통 파일을 각자 다르게 고치지 않는다. 수정이 필요하면 contract-change PR 선행 후 동일 revision을 소비한다. 개인별 실제수정 파일은 기존작업카드의 상세 소유 경계를 유지한다.

선행 PR6단계: (1)이 계약/합의→(2)additive DB+API/capability disabled→(3)Core owner/claim+collector→(4)Content16/localblur→(5)UI/API/effect연결+coordinatedfocus→(6)통합/회귀/릴리스검증. 각 담당 Codex는 카드단위 구현→자동시험→오류원인분석/최소수정→재검증→독립Chrome→PR을 책임진다. 일반오류/실패는 스스로 해결, 팀장에게 정책변경/공통계약충돌/보안위험/범위초과/최종통합문제만 요청한다. 완료보고만으로 완료 아님: commit/artifact hash, 환경/명령/실제값/기대값/오차, PASS·FAIL·NOT_RUN과 원본실패증거가 필요하다. 팀장은최종통합/전체회귀/릴리스판정. force/reset/clean/타인미커밋덮어쓰기 금지, 소유범위만명시stage, 관련시험통과후 PR; 실제합의전자동merge없음.
