| 사용자 확정 | RC1 규칙 |
|---|---|
| DEC-01 | 이용시간 수집/집행은 집중과 독립적인 상시 browser runtime |
| DEC-02 | 설치별 일일 한도, 계정 합계는 조회만; 다중 설치 동시 시간은 기기 합계 |

| DEC-06 | 현재 사용자 날짜 종료 후 새 timezone, 원장/현재 사용 재계산·삭제 금지, 잔여 예산 승계/중복 부여 금지 |
| DEC-07 | 명시 선택한 게스트 완료 기록만 회원 분석 import, 원본 보존/중복 방지/현재 회원 quota 자동 가산 금지 |

## 판정 순서와 충돌 벡터

실행 candidate: 검증된 owner/package를 고정 → 기존 frozen focus에서 legacy host row 선택 → 독립 제약 reason set 합성 → reason 있으면 BLOCK → 없으면 focus BLOCK/ALLOW/RECORD → 기능 옵션 적용. global 이유에 대한 exception은 그 이유에만 적용한다. adult exception이 quota를 해제하거나 focus ALLOW가 adult를 해제하지 않는다. 허용 시간창은 한 정책 내 union, 서로 다른 matching time 정책은 AND 제안이다. explicit block window는 한 개만 매치해도 차단. exact/subdomain은 label boundary이며 example.test는 evil-example.test에 매치하지 않는다. time 정책 모든매치 합성은 C06 공동 검토 필요; legacy 최장 host row 규칙은 변경하지 않는다.

| 사례 | 결과 |
|---|---|
| focus ALLOW + quota exhausted | 해당 site BLOCK/DAILY_LIMIT, focus RUNNING 유지 |
| focus RECORD + block schedule | BLOCK/BLOCK_WINDOW, 확정된 한 navigation 이벤트 |
| adult exception + quota | adult reason만 제거, DAILY_LIMIT 유지 |
| keyword exception + adult | keyword만 제거, ADULT_DOMAIN 유지 |
| focus END + runtime block | focus claim만 해제; runtime 유지 |
| focus PAUSE + quota | focus 해제 실제 확인 후 PAUSED; quota 유지 |
| runtime quota midnight reset + focus BLOCK | quota reason만 해제; focus BLOCK 유지 |
| 하위도메인 ALLOW + 부모 time limit | candidate 모든 matching time constraints 적용, ALLOW 우회 불가 |
| daily limit null + outside allow window | 무제한 quota와 무관하게 OUTSIDE_ALLOW_WINDOW |
| 한 정책 허용창 두 개 겹침 | union으로 한 번만 허용, 사용시간 한 번만 계수 |
| 서로 다른 정책 허용창 겹치지 않음 | 교집합 없음→계속 차단, 설정 충돌 안내 |
| 새 정책 active unsupported | 적용 전 전체 거절, 기존 verified package 유지 |
| focus 중 설정 저장 | frozen focus 불변, runtime 대상만 별도 revision 적용 |
| 소유 전환 중 오래된 ACK | stale owner_epoch 거절, 새 소유 효과로 인정 안 함 |

## 측정과 원장

활성 탭 + 전경 focused Chrome window + http(s) actual host + unlocked/not-idle 상태를 수집 대상으로 하는 후보 기준이다. idle threshold60초는 기술/제품 공동 검토 대상이며 즉시 확정하지 않는다. background tabs·포커스 없는 창·다른 앱·브라우저 내부 페이지·DevTools inspection는 수집하지 않는다. 같은 설치에서 동시 여러창을 합산하지 않고 하나의 foreground interval만 기록한다. 여러 정책에 attribution해도 physical segment 시간은 한 번만 계정 합계에 반영한다. focus 시간과 browser 시간은 다른 통계이며 합산 금지.

활성 tab/window/url/close/idle/owner/day/revision 경계마다 정산, interval은 monotonic elapsed로 계산하고 UTC 경계/epoch와 연결한다. wall clock rollback/jump는 PARTIAL+재앵커링, 음수/공백을 확인시간으로 만들지 않는다. day boundary를 넘는 interval은 두 immutable segment로 분할한다. same-host tab전환도 single collector를 유지한다. persisted epoch+seq+prevhash, interval overlap 검증 및 동일 item hash가 Worker 복원/재전송 이중 계수를 막는다. seq gap은 UNKNOWN/PARTIAL이며 0 사용으로 채우지 않는다.

체크포인트5초/경계오차5초/차단6초는 **검증 목표**다. 기존 PoC max unsaved6.012초는 strict5초 FAIL, quota1.454초는 단일 관측, 혼합420.333초 대비420.006초(차이−.328±.235초)는 연속30분/2시간 정확도를 증명하지 않는다. 신규 제품 Chrome 시험은 NOT_RUN이다. 현실적 승인안은 사건 정산+durable marker+재시작 loss bound 실측을 채택하고 max unsaved/p50/p95/p99/absolute max를 보고하는 것이다. 강제 종료 loss가 모르면 UNKNOWN으로 남긴다.

Chrome service worker는 유휴 종료될 수 있고 alarms는30초 최솟값·추가 지연이 있어5초 지속 실행 보장이 아니다. keepalive 우회·offscreen 목적 위장·debugger 상시 연결로 성능 목표를 맞추지 않는다. 근거: [Worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms). 실제 성능 승인에는 debugger 없는 독립 신규 profile, 전경30분/2h, 반복전환, idle Worker 재생성, 정상/강제 종료, 저장 fault, offline, 실제 차단측정이 필요하다.

## 자정·시간대·DST

정상 day는 local midnight→다음 local midnight로 계산하여 DST 23h/25h를 보존한다. timezone 변경 desired는 마지막 요청이 pending update할 수 있지만 effective_at은 최초 현재 day 종료 경계로 고정; 적용전 되돌리기도 사용량 reset을 만들지 않는다. 기존 zone 종료 instant E에서 새 zone 다음 midnight N까지 transition bucket `[E,N)`을 열고 **남은 예산만** 승계한다. N에서 정상 새day로 전환한다. budget_carry_debit=max(0,new limit−old remaining)이며 원본 confirmed_ms와 분리한다. 이미 소진된 예산은 transition에서도0, 한도 하향은min(old remaining,new limit), 상향으로 당일 사용을 지우지 않는다. 여러 번 zone 변경해도 같은 enforcement chain의 잔여 floor를 유지한다. 이 연산은 DEC-06 준수 결정안이며 exact representation은3인 검토다.

회원전환은 DEC-07 import와 별도다. 권장: 같은 설치 로컬 enforcement_day_chain의 잔여 floor를 이어 우회를 막되 게스트 raw segments를 회원 업로드하지 않는다. alternatives: owner별 완전 독립 budget(로그인 우회 위험), 서버 opaque carry summary(개인정보/권한 승인 추가). 어떤 안도 user policy 승인으로 소급 표기하지 않으며 joint review 전제품 적용 금지.

schedule ONCE는 UTC start/end, WEEKLY는 IANA/요일1..7/start/end/end_day_offset, 정확한 occurrence ID는 config/version/localdate/zoneversion/fold에 결속한다. DST gap SKIP, fold EARLIER_ONCE는 제안이며 임의 1시간 밀어서 다른 시간에 차단하지 않는다. overnight은 end_day_offset1, 0길이/24h초과 금지. focus 예약은 기존 활성 session 우선 WAITING_CONFLICT; 고정 end 후 EXPIRED, 중복발생 금지, 잔여60초 미만 새세션 안 함. Chrome 종료중 놓친 focus를 무조건 시작하지 않는다. site block window는 재시작 현재 시각 membership으로 재조정하며 놓친 시간을 소급 block하지 않는다.

반복 focus는 cycle별 실제 검증된 active time을 사용, rest는 elapsed wall clock 후보다. 사용자가 선택한 repeat/autostart만 적용하고 focus deadline(예약 fixedend)이 먼저면 중단한다. rest중 runtime 정책은 유지한다. crash/restart에서 missed focus 자동 catch-up 금지, 복원 불확실시 WAIT_USER/UNKNOWN. cycles1..12/rest1..180/daily limit1..1440분/분단위는 검토안이며 기존 사용자 정책으로 확정된 숫자가 아니다.
