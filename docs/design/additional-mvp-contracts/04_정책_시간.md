## 판정 순서와 충돌 벡터

실행 candidate: 검증된 owner/package를 고정 → 기존 frozen focus에서 legacy host row 선택 → 독립 제약 reason set 합성 → reason 있으면 BLOCK → 없으면 focus BLOCK/ALLOW/RECORD → 기능 옵션 적용. global 이유에 대한 exception은 그 이유에만 적용한다. adult exception이 quota를 해제하거나 focus ALLOW가 adult를 해제하지 않는다. 허용 시간창은 한 정책 내 union, 서로 다른 matching time 정책은 AND 제안이다. explicit block window는 한 개만 매치해도 차단. exact/subdomain은 label boundary이며 example.test는 evil-example.test에 매치하지 않는다. time 정책 모든매치 합성은 C06 공동 검토 필요; legacy 최장 host row 규칙은 변경하지 않는다.

## 측정과 원장

활성 탭 + 전경 focused Chrome window + http(s) actual host + unlocked/not-idle 상태를 수집 대상으로 하는 후보 기준이다. idle threshold60초는 기술/제품 공동 검토 대상이며 즉시 확정하지 않는다. background tabs·포커스 없는 창·다른 앱·브라우저 내부 페이지·DevTools inspection는 수집하지 않는다. 같은 설치에서 동시 여러창을 합산하지 않고 하나의 foreground interval만 기록한다. 여러 정책에 attribution해도 physical segment 시간은 한 번만 계정 합계에 반영한다. focus 시간과 browser 시간은 다른 통계이며 합산 금지.

활성 tab/window/url/close/idle/owner/day/revision 경계마다 정산, interval은 monotonic elapsed로 계산하고 UTC 경계/epoch와 연결한다. wall clock rollback/jump는 PARTIAL+재앵커링, 음수/공백을 확인시간으로 만들지 않는다. day boundary를 넘는 interval은 두 immutable segment로 분할한다. same-host tab전환도 single collector를 유지한다. persisted epoch+seq+prevhash, interval overlap 검증 및 동일 item hash가 Worker 복원/재전송 이중 계수를 막는다. seq gap은 UNKNOWN/PARTIAL이며 0 사용으로 채우지 않는다.

체크포인트5초/경계오차5초/차단6초는 **검증 목표**다. 기존 PoC max unsaved6.012초는 strict5초 FAIL, quota1.454초는 단일 관측, 혼합420.333초 대비420.006초(차이−.328±.235초)는 연속30분/2시간 정확도를 증명하지 않는다. 신규 제품 Chrome 시험은 NOT_RUN이다. 현실적 승인안은 사건 정산+durable marker+재시작 loss bound 실측을 채택하고 max unsaved/p50/p95/p99/absolute max를 보고하는 것이다. 강제 종료 loss가 모르면 UNKNOWN으로 남긴다.

Chrome service worker는 유휴 종료될 수 있고 alarms는30초 최솟값·추가 지연이 있어5초 지속 실행 보장이 아니다. keepalive 우회·offscreen 목적 위장·debugger 상시 연결로 성능 목표를 맞추지 않는다. 근거: [Worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms). 실제 성능 승인에는 debugger 없는 독립 신규 profile, 전경30분/2h, 반복전환, idle Worker 재생성, 정상/강제 종료, 저장 fault, offline, 실제 차단측정이 필요하다.

## 자정·시간대·DST

정상 day는 local midnight→다음 local midnight로 계산하여 DST 23h/25h를 보존한다. timezone 변경 desired는 마지막 요청이 pending update할 수 있지만 effective_at은 최초 현재 day 종료 경계로 고정; 적용전 되돌리기도 사용량 reset을 만들지 않는다. 기존 zone 종료 instant E에서 새 zone 다음 midnight N까지 transition bucket `[E,N)`을 열고 **남은 예산만** 승계한다. N에서 정상 새day로 전환한다. budget_carry_debit=max(0,new limit−old remaining)이며 원본 confirmed_ms와 분리한다. 이미 소진된 예산은 transition에서도0, 한도 하향은min(old remaining,new limit), 상향으로 당일 사용을 지우지 않는다. 여러 번 zone 변경해도 같은 enforcement chain의 잔여 floor를 유지한다. 이 연산은 DEC-06 준수 결정안이며 exact representation은3인 검토다.

회원전환은 DEC-07 import와 별도다. 권장: 같은 설치 로컬 enforcement_day_chain의 잔여 floor를 이어 우회를 막되 게스트 raw segments를 회원 업로드하지 않는다. alternatives: owner별 완전 독립 budget(로그인 우회 위험), 서버 opaque carry summary(개인정보/권한 승인 추가). 어떤 안도 user policy 승인으로 소급 표기하지 않으며 joint review 전제품 적용 금지.

schedule ONCE는 UTC start/end, WEEKLY는 IANA/요일1..7/start/end/end_day_offset, 정확한 occurrence ID는 config/version/localdate/zoneversion/fold에 결속한다. DST gap SKIP, fold EARLIER_ONCE는 제안이며 임의 1시간 밀어서 다른 시간에 차단하지 않는다. overnight은 end_day_offset1, 0길이/24h초과 금지. focus 예약은 기존 활성 session 우선 WAITING_CONFLICT; 고정 end 후 EXPIRED, 중복발생 금지, 잔여60초 미만 새세션 안 함. Chrome 종료중 놓친 focus를 무조건 시작하지 않는다. site block window는 재시작 현재 시각 membership으로 재조정하며 놓친 시간을 소급 block하지 않는다.

반복 focus는 cycle별 실제 검증된 active time을 사용, rest는 elapsed wall clock 후보다. 사용자가 선택한 repeat/autostart만 적용하고 focus deadline(예약 fixedend)이 먼저면 중단한다. rest중 runtime 정책은 유지한다. crash/restart에서 missed focus 자동 catch-up 금지, 복원 불확실시 WAIT_USER/UNKNOWN. cycles1..12/rest1..180/daily limit1..1440분/분단위는 검토안이며 기존 사용자 정책으로 확정된 숫자가 아니다.

## RC2 C-02: monotonic 원장·UTC 이상·재처리

`clock_epoch/boot_id/anchor_id`, `anchor_utc/anchor_mono_ms`, `mono_start_ms/mono_end_ms`, `observed_wall_start_at/end_at`, quality를 필수로 한다. 투영 UTC는 `anchor_utc + (mono - anchor_mono_ms)`, duration은 양의 monotonic 차이다. UTC 관측과 투영 차이는 인증된 calibration tolerance와 비교하며 client가 품질 TRUSTED를 보내는 것만으로 신뢰하지 않는다. 순수 참조 모델은 권한 있는 fixture registry에 anchor를 등록하는 시험이며 실제 보정 수단 승인은 대기한다.

같은 설치·boot의 monotonic 반개구간 overlap은 clock_epoch 이름이 바뀌어도 계속 거절한다. 서로 다른 실제 구간이 같은 UTC로 보인다는 이유만으로 overlap 거절·삭제하지 않는다. 동일 segment/hash 재전송은 멱등, 같은 ID 다른 hash/같은 collector epoch·seq 다른 segment/chain 단절은 거절한다. gap은 보류 후 같은 원본을 재전송한다. 시계 이상 구간도 durable raw 접수 후 seq/prevhash를 전진하므로 다음 정상 구간을 영구 막지 않는다.

ROLLBACK/FORWARD_JUMP/RESTART_UNCONFIRMED는 raw를 QUARANTINED로 보존하고 confirmed_ms=0, uncertain_ms=monotonic duration으로 둔다. 서버 집계 COUNTED와 접수 ACCEPTED는 별개다. 정상 raw를 불신 구간과 섞지 않고 경계 분할한다. raw 계산 day는 투영 범위에 맞춰 보존하고 검증된 실제 UTC/day는 별도 resolution으로만 교정한다. 정상 day와 DEC-06 전환 bucket 둘 다 권한 있는 day allocation과 대조한다.

Worker 재생성에서 collector seq/hash는 durable cursor를 복구한다. monotonic 기준을 잃으면 새 boot/clock anchor를 발급하고 직전 raw hash에 연결한 재시작 증명을 확인할 때까지 격리한다. 브라우저가 닫힌 공백이나 검증되지 않은 앞당김 시간을 만들어내지 않는다. 유효한 다음 anchor로 확인된 구간은 격리 predecessor 뒤에서도 계속 집계한다. 기존 회원 전환의 로컬 enforcement chain과 DEC-07 과거 분석 import 구분은 그대로다.

정상 IANA 자정에서 split, DST는 실제 23h/25h, DEC-06은 날짜 종료 후 변경+남은 예산 승계이며 UTC 재계산으로 이중 allowance를 주지 않는다. 격리 interval의 quota는 아래 C05 선택 반영 규칙을 따른다. QUARANTINED를 임의 COUNTED로 바꾸거나 사용량0으로 표시하여 통계·한도를 우회하지 않는다.

재처리는 source_hash·같은 physical capture·capture timezone/version/enforcement chain·검증된 anchor/보정 UTC/day를 결속한 immutable resolution으로 수행한다. 격리 raw/chain은 그대로, resolution_id+hash 멱등·segment당 확정 한 번·집계 한 번이다. 미검증 증거, 틀린 owner/capture, 두 번째 다른 resolution은 거절한다. 검증 불가 구간은 PARTIAL/UNKNOWN으로 남기며 자동 추정 확정하지 않는다. clock anomaly·자정·DST·Worker 재시작·재처리는 합성 시험, 실제 OS clock 변경/Chrome 재시작 성능은 NOT_RUN이다.

## 최종 교차 검증의 원장 보완

boot_id는 한 monotonic 기준 수명의 식별자다. clock_epoch 이름만 바꾸어 같은 실제 구간을 새 물리 영역으로 만들 수 없다. mono 기준을 실제 잃으면 새 boot와 검증된 재앵커링이 필요하다. geometry/chain/물리 overlap으로 거절한 요청은 새 sequence 위치를 점유하지 않는다. 유효한 gap 원본을 보류할 때만 위치를 예약하고 해시를 고정한다. 이미 접수된 raw의 ID/seq 변경은 계속 금지한다.

ClockResolution의 멱등성은 proof뿐 아니라 anchor_id를 포함한 전체 envelope hash에도 결속한다. 같은 resolution_id의 anchor·날짜·확정량 변경은 같은 proof를 제시해도 거절한다. 원본 raw/chain은 수정하지 않고 확정 집계는 한 번만 수행한다. 이 보완으로 rejected 요청의 순번 오염·epoch 재명명 overlap 우회·resolution envelope 변조를 각각 반례로 검증했다.

## C01·C02 frozen 단위

coordinated START에서 Snapshot ID/format/hash/실제 payload와 Attachment ID/payload_sha256/config_revision/content를 불변 저장한다. PAUSE는 자기 focus claim 해제 확인 후 확정하며 runtime claim은 유지한다. RESUME은 이 두 원본을 함께 조회·대조해 재적용하고 latest CONTENT/config를 다시 읽어 새 옵션을 섞지 않는다. 같은 Attachment ID라도 hash/내용이 다르면 거절한다. 세션 중 저장한 새 옵션은 다음 세션 대상이며 frozen 포인터를 갱신하지 않는다. Attachment가 없는 세션도 null이라는 사실을 고정하여 RESUME 때 새 Attachment를 주입하지 않는다. 기존 Member/Guest D06 actor·Snapshot 원문은 불변, 신규 coordinated stream만 사용한다.

## C05 확정 통계와 provisional 한도

1. confirmed_ms는 검증된 정상 raw 또는 단 한 번의 검증 resolution만 합산한다. QUARANTINED/raw·source hash·seq를 지우거나0초 정상 기록으로 변환하지 않는다. 이미 확정/이월/이전 집행한 debit은 불확실하다는 이유로 감소시키지 않는다.
2. 새 불확실 구간의 물리 monotonic 길이와 유효 day/chain이 검증되면 그 길이를 **provisional reservation**으로 해당 설치·matching policy 각각에 한 번만 예약한다. 통계에는 미확정, 집행에는 차감이다. 키는 기존 source item/hash/chain/policy/day이며 중복 replay로 다시 차감하지 않는다. 같은 ID 다른 hash는 거절한다. local sidecar의 단일 transaction에 raw/cursor/reservation/outbox를 함께 보존한다. 실제로 저장 못 하면 저장 성공을 가정하지 않는다.
3. 길이·day/chain·연속성을 검증할 수 없는 새 gap은 시간을 만들어 차감하지 않는다. 해당 설치의 한도 적용 사이트만 MEASUREMENT_UNCONFIRMED로 일시 제한하고 focus session·다른 owner 정책은 유지한다. 기존 소진 DAILY_LIMIT도 유지한다. 미관측 구간을 새 날짜 allowance나 로그인 초기화로 우회하지 않는다. 불확실 시간은 전역 모든 사이트 차단 근거가 아니다.
4. 잔여=max(0,limit−기존 확정/이월/집행 debit−미해소의 유효 provisional 합). 미정 길이/day hold가 있으면 로컬 집행 잔여0이나, UI는 '사용량0/정상 소진'이 아니라 측정 미확인으로 표시한다. 서버가 미보고 local reservation을 안다고 가정하지 않는다. 확인할 수 없는 최신 remaining은 DailyUsage의 remaining_ms=null·quality UNKNOWN/PARTIAL·enforcement UNKNOWN/PENDING과 as_of로 표시한다. 현재 제한이 실제 적용됐다는 ACK가 없으면 APPLIED로 표시하지 않는다.
5. 검증된 anchor·source hash·물리 capture/day allocation에 결속한 기존 immutable resolution만 예약을 확정량으로 **대체**한다. 이중 차감 금지, segment당 최종 resolution 하나·동일 hash 재전송 멱등. 기존 ClockResolution은 exact 양의 physical duration을 보존하므로 길이가 이미 알려진5000ms 예약을 임의3000ms나0으로 줄여 해제하지 않는다. 미정 길이/day hold는 실제 원본 구간의 길이·day가 검증된 뒤에만 해소하고 기존 unrelated debit은 보존한다. 증거 없는 자동 해제/잔여 증액은 금지한다. 검증 불가이면 hold/미확정 의무를 남긴다.
6. Core collector는 monotonic/boot·관측 UTC의 anchor 후보 생성과 durable cursor 복구를 담당한다. 회원의 trusted anchor/resolution 등록·검증·원자 집계는 Server의 권한 있는 validator가 담당하며 기존 설치/owner 인증·Native/browser 관측 adapter와 검증된 calibration 근거를 결속한다. Server가 직접 client performance.now를 관측했다고 주장하지 않는다. Native/Worker가 임의 보낸 TRUSTED 플래그나 로컬 wall clock만으로 인증하지 않는다.
7. Worker 복원은 raw/cursor/이전 reservation→실제 관측→재앵커링 증거→수집 재개 순서다. mono 수명 소실이면 새 boot/anchor와 predecessor proof가 필요하다. 비회원은 Core의 로컬 검증 경로와 같은 증거 기준을 쓰며 신뢰 근거가 없으면 격리를 유지한다. 이 계약은 검증 책임을 지정할 뿐 기존 Server/Native에 보정 API가 구현됐다고 가정하지 않는다. 실제 anchor 발급 adapter를 입증하기 전 해당 profile 활성화는 금지한다.

5초 checkpoint/경계·6초 차단은 목표이고 기존6.012초 FAIL은 보존한다. 이 선택 동의가 새 SLA나30분/2시간 PASS는 아니다.

## C11 idle60초와 불가 상태

idle 권한과 API를 사용할 때 threshold60초로 queryState/onStateChanged를 연결한다. '마지막 입력 직후부터 즉시 idle'로 취급하지 않는다. **마지막 입력부터 idle 판정 전 첫60초는**, 다른 수집 조건이 맞으면 전경 이용시간으로 계산하고 idle 전환 시60초를 소급 빼지 않는다. idle/locked를 관측하면 직전 구간 정산 후 이후 수집을 중단하고 active 복귀 후 새 관측 경계에서 재개한다. 탭/창 전환도 각각 정산하여 background 시간을 이어 붙이지 않는다.

Chrome API는 정확한 마지막 입력 timestamp를 제공한다고 가정하지 않는다. 알림 지연·Worker 관측 공백은60초 정확 판정 성공이 아니다. 확정 가능한 prefix와 미확인 tail을 구분하고 tail은 C05 예약/hold로 처리한다. 합성 정시60초 시험과 실제 callback 지연 시험을 구분한다.

권한 거절/소실·API 미지원/오류·재생성 후 최초 상태 미관측은 IDLE_UNAVAILABLE/quality UNKNOWN이다. 기존 debit/원본을 보존하고 해당 한도 사이트는 측정 복구 전 일시 제한한다. 한도 없는 사이트는 전체 차단하지 않되 미수집을0 또는 COMPLETE로 표시하지 않는다. UI에 '측정 권한/기능 확인 필요, 이용 한도 사이트 일시 제한'과 복구 절차를 안내한다. 권한 재확인·실제 idle state/frame/anchor·원장 복구를 완료한 뒤 새 구간을 시작하며 공백을 소급 정상 계수하지 않는다. 실제 제한 실패도 APPLIED로 위장하지 않는다. manifest/프로필은 이번 계약 PR에서 변경하지 않는다.
