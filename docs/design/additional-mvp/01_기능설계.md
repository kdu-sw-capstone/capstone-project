## 1·2. YouTube 10개 / Instagram 6개

공통 적용안: HTTPS 데스크톱 웹 `youtube.com/www.youtube.com`, `instagram.com/www.instagram.com`만 초기 대상. 모바일 웹·앱·임베드·다른 host는 UNSUPPORTED. 로그인 여부·언어·DOM 변형은 별도 검증한다. 각 기능 ON은 아래 대상 제한, OFF는 해당 기능의 소유 변경만 복원한다. 설정 저장은 다음 세션 frozen Snapshot에 반영한다. 세션 도중 설정을 바꾸어도 현재 정책은 변경하지 않는다.

초기 문서·SPA 경로 변경·동적 DOM을 관찰하고 변경분에만 적용한다. document/owner/session/snapshot/revision 검증을 통과한 Core 지시만 수용한다. 페이지 스크립트의 명령·자체 주장으로 성공을 확정하지 않는다. 페이지에 대상이 없는 NOT_APPLICABLE과 있어야 할 대상을 감지하지 못한 FAILED, 환경 미지원 UNSUPPORTED를 구분하는 내부 결과안을 사용한다. 이 결과안을 기존 capability wire enum으로 무단 추가하지 않는다.

실패 시 해당 기능의 적용 미확인을 표시하며 성공 통계에서 제외한다. 활성 필수 정책 적용을 확인할 수 없으면 부분 성공 RUNNING으로 표시하지 않고 기존 실패 정리/UNKNOWN 흐름을 따른다. 단순 영역 숨김·흑백 처리는 접근 이벤트가 아니다. 기능 경로 진입만 Core의 navigation 기준으로 접근 후보를 만든다. 종료·정지에서는 소유 스타일/속성만 복원하며 사이트·다른 확장·사용자 변경을 덮어쓰지 않는다.

## 3. URL 중심 키워드 차단 — OPTION-09

사용자 최신 확정 범위는 URL 전용·제목/본문/댓글/작성문장 제외다. 신규 정책은 URL_BOUNDARY_V1로 설계하고 기존 TITLE/BODY 설정·과거 Snapshot 원문은 보존한다. 구 설정을 신규세션에 전환하는 명시확인 절차는 계약검토 대상이다. http(s) URL의 hostname/path/query를 로컬에서 비교하며 fragment 제외를 권장한다(세부결정 대기). 사용자정보·전체 URL·검색어를 서버 이벤트/로그에 저장하지 않는다.

2차 비교안: http(s) URL을 표준 parser로 분해해 host/path/query의 각 component만 검사한다. credentials·port·fragment는 대상 제외, scheme/host 오인식 금지. path/query는 유효한 percent sequence만 UTF-8 1회 디코드하며 malformed component는 불명으로 표시하고 그것만으로 차단하지 않는다. query는 key/value별 비교, `+` 공백 해석은 query에만 적용한다. host는 IDNA 정규화 후 label별 비교하고 Unicode 표시형과 ASCII형 중 동일 정규화 정책을 fixture로 고정한다. 모든 component에 NFKC+Unicode case-fold 후보를 적용하고 공백을 정리한다. 키워드 1~80자·최대200·정규화 중복 거절. 경계는 앞뒤가 Unicode Letter/Number/Mark 또는 `_`가 아닌 위치(시작/끝 포함)로 제안한다. `game`은 `/game/`, `q=game`에 일치하나 `/gamer/`에는 불일치, `게임`은 `/게임/`에 일치하나 `게임기`에는 불일치. 다단어는 component 내부 연속 phrase만 비교하고 host/path/query를 이어 붙여 가짜 경계를 만들지 않는다. 한국어 합성어 허용·하이픈/언더스코어 규칙은 제품 승인 항목이다. 페이지 제목/본문/댓글·입력/editable은 읽지 않고 번역·동의어 확장도 하지 않는다. 전체 URL·키워드 원문을 Core 이벤트로 내보내지 않는다. 새로운 URL 정책에 legacy scopes/예외를 숨겨 자동 적용하지 않는다. 예외 유지 여부는 PROP-09에 남기며 역사 원문은 보존한다.

AC-URL-01: 대소문자·전각·한글 인코딩·잘못된 %·query 변화 결과가 정의대로 일치. AC-URL-02: 키워드 예외가 USER_SITE/ADULT_DOMAIN을 해제하지 않음. AC-URL-03: 같은 navigation 여러 매칭은 한 접근, payload 원문 불변. AC-URL-04: URL/매칭 텍스트 외부 유출 없음, 미지원 scheme은 미검사 표시. 기존 AC-OPTION-09-01~03 유지·보완.

AC-URL-05: 위 경계 positive/negative·double encoding·invalid UTF8·query plus·fragment-only 이동·push/replace/pop을 fixture로 검증. 구 AC-OPTION-09의 본문 검사/단순 부분일치 기대값은 새 정책 적용분에서 변경 제안이며, 구 Snapshot의 기대값과 분리한다. 확정 전 서버 schema를 변경하지 않는다.

## 4. StevenBlack 성인 사이트 — OPTION-10

StevenBlack의 기본 통합 hosts 전체를 성인 목록으로 쓰지 않는다. porn 전용 출처를 추출·정규화한 FOCURVE 배포 artifact를 제안한다. upstream commit·원본 URL·원본/산출 SHA256·source별 라이선스·추출 규칙·건수·검수 시각을 manifest에 고정한다. upstream의 base 광고/추적 목록을 섞어 오차단하지 않는다. 목록 선택·라이선스 적합성·DNR 용량은 아직 검증 전이다.

Server는 배포 metadata, Core는 검증된 목록·자기 소유 규칙 설치/실제 확인을 담당한다. Content는 페이지 제한 표시·관측을 연계한다. 원격 실행 코드는 받지 않는다. 새 artifact 전체 검증 후 원자 교체, 실패 시 마지막 검증본 유지. 최초 유효 목록 없으면 기능 사용 불가, 정상 보호 중 표시 금지. catalog version은 세션에 고정하고 활성 세션 중 무단 교체하지 않는다. 예외는 해당 목록에만 적용하고 직접 BLOCK·키워드 차단을 해제하지 않는다.
